# Zombie Defense · 四向僵尸防守

实时士兵微操防守游戏：进入游戏先选择故事模式或场景演练；故事从小屋内部开始，三波通关后前往大楼楼下，第二关同样三波。当前默认 15 名士兵，僵尸从地图四边分批进入，玩家用手指在固定范围内选中一名士兵并拖拽微操。独立 TypeScript 核心负责战斗规则，Cocos Creator 3.8.8 适配层负责输入、Graphics 绘制与 HUD。

场景已独立为 `src/scenes/` 内容模块，第二关使用更宽、更长的长方形建筑墙体。查看 [故事与场景设计稿](docs/10-story-scenes-design.md) 和可在浏览器中直接打开的 [交互设计预览](docs/design/scenes-preview.html)。场景回归运行 `npm run test:scenes`；下文保存的旧验收数字属于此前配置，不代表当前人数与分批出怪设置的测试结果。

**当前是已做无渲染验证的核心与已编写的 Cocos 场景适配层。Creator 导入、预览、Web Mobile/微信构建及真机性能尚未验证，不能视为可发布版本。**

## 快速开始

准备独立安装的 **Node.js v26.8.1** 和 npm。v26.8.1 是本轮执行验证使用的版本；项目尚无 `engines` 约束或版本矩阵，不宣称 Node 20/22 或其他版本兼容。Creator 自带 Node 不替代此前置条件。

在完整源码根目录执行：

```sh
npm ci
npm run sync:core
npm test
npm run typecheck
npm run typecheck:cocos
npm run check:cocos-bundle
```

这些命令不会启动游戏画面。`npm test` 自动同步生成核心；bundle 检查**不是引擎构建**。可视运行请按 [上手与使用](docs/getting-started.md) 安装 Creator 3.8.8，导入 `assets/scenes/Battle.scene`。完整测试含 20 局重启回归和临时源码副本的真实依赖安装，耗时较长且需要网络。

## 当前规则与证据

3秒布阵结束才启动战斗钟，无跳过入口；波次在0/7/20s触发，不等待清场。A/B/C是士兵分组与僵尸统计标签，僵尸从北、南、东、西边缘进入并全场最近索敌，28px内按间隔攻击。僵尸可绕墙追击，墙边同一堆达到3只仍可翻墙；翻墙期间不受分离推力干扰，落地后恢复最小间距分离。每次按下仅选中112px圆内距离最近的一名存活士兵，不沿用原整组选中或矩形框选；该士兵向松手点附近靠拢，移动中仍会自动索敌和射击。全灭失败优先。50ms固定步进。

当前配置：最多15名士兵，步枪射程260px，士兵速度48px/s，略快于僵尸的41.9px/s；步枪每0.35s一发、单发30点伤害，僵尸60HP、攻击间隔0.13s。士兵在波次之间持续留场，不会因新一波开始而重置。僵尸按每批5只、每秒一批从四边进入，前一波和后一波可以同时在场。士兵和僵尸的显示直径都已放大为原来的两倍。射击须同时满足距离和墙体遮挡判断，飞行途中碰墙即停止，目标中途躲到墙后也不会扣血；拖拽时显示固定选择圆与一名士兵的射程参考圈。枪口闪光、飞行亮线与弹头显示射击方向，命中弹道保留0.10s，近距离也可见；边框保持静态中性色，不再红色闪动。

当前四向地图的整局验收覆盖挂机、开局单兵微操和不同帧分段回放，实测结果见 [JSON报告](docs/testing/mvp-test-report.json)。每关三波共350只僵尸，按每批5只、每秒一批从四边进入；士兵跨波保留。seed当前不影响随机战斗；种子1–10结果一致，完整状态/事件在不同帧分段下等价。

可选微信破门短振动已实现，同批合并、1000ms限频，物理效果未验证。墙侧阴影和复杂场景确认延期；卡顿策略待Cocos反馈，GitHub/许可证/发布暂缓。[用户Cocos手测清单与模板](docs/testing/cocos-manual-checklist.md)用于后续记录，自动化通过不等于平台验收。实际测试计数及检查结果见本轮Task3/4交付报告；旧99项记录不代表当前套件。
