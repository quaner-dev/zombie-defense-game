# 新场景设计：别墅解救平民（连续生成版）

> 状态：提案设计稿，当前只落地文档，不修改战斗代码、场景配置或 Cocos 资源。
>
> 本稿已经根据最新需求收敛为单一目标：6 名平民保持平民状态并被成功保护。场景不使用战斗波次、入口突入、内部墙体、评分、星级或额外评级条件。

## 1. 场景目标和核心规则

别墅是由四面首尾相连的外墙组成的封闭空间。6 名平民和 7 名士兵在战斗开始时已经位于别墅内部，士兵直接围绕平民生成，形成保护圈。僵尸从别墅外四个方向逐渐生成，先攻击外墙；墙体被击穿后，僵尸通过缺口进入内部，士兵在平民周围抵御入侵。

本关只验收“解救平民”这一件事：

- **保护目标**：6 名平民全部保持为平民，不能被僵尸有效攻击并完成变身。
- **平民行为**：平民原地不移动、不攻击、不接受玩家指令。
- **士兵行为**：战斗开始即处于中央保护圈，可以按现有规则被玩家选择和拖拽调整。
- **僵尸行为**：持续生成，不按波次分组；从外墙四侧靠近并攻击墙体，破墙后进入室内。
- **失败条件**：任意一名平民完成变身为普通僵尸，立即判定解救失败。
- **胜利条件**：连续生成调度达到本关的生成上限，场上僵尸全部清除，且 6 名平民仍保持平民状态。

这里的“生成上限”只是为了让关卡拥有可验证的结束点，不产生评分或星级。结算页面只显示“解救成功”或“解救失败”，不比较用时、伤亡、墙体耐久或击杀数。

## 2. 空间布局

### 2.1 坐标和封闭边界

沿用项目当前地图坐标：原点在左上，逻辑尺寸为 `1080×2400`，战斗边界为 `x=60..1020、y=180..2160`。别墅室内区域为 `x=124..956、y=424..2000`。四面墙首尾相连，四个角不留缺口，也没有门、窗、入口或室内隔断。

| 墙体 | 逻辑范围 | 连接关系 | 首版规则 |
|---|---|---|---|
| 北墙 `villa-wall-north` | `x=100..980, y=400..424` | 连接西墙、东墙 | 阻挡移动；可受僵尸攻击；击穿后在受击位置形成缺口 |
| 西墙 `villa-wall-west` | `x=100..124, y=400..2024` | 连接北墙、南墙 | 阻挡移动；可受僵尸攻击；击穿后在受击位置形成缺口 |
| 东墙 `villa-wall-east` | `x=956..980, y=400..2024` | 连接北墙、南墙 | 阻挡移动；可受僵尸攻击；击穿后在受击位置形成缺口 |
| 南墙 `villa-wall-south` | `x=100..980, y=2000..2024` | 连接西墙、东墙 | 阻挡移动；可受僵尸攻击；击穿后在受击位置形成缺口 |

四面墙体在视觉上是连续的别墅外墙，而不是四块互相分离的掩体。墙体初始没有缺口，僵尸必须先对墙造成足够伤害才能进入。墙体受到攻击时只在最近受击点生成局部缺口，不能把整面墙瞬间删除；这样仍然保持“四面墙组成封闭别墅”的视觉，同时形成逐渐失守的空间变化。

### 2.2 墙体耐久和缺口

每面墙使用独立耐久，建议初始值为 `1800 HP`。同一面墙可以在多个位置受到攻击，但首版只保留一个活动缺口：新的受击点与已有缺口距离小于 `160px` 时合并为同一缺口，否则把受击点排队到当前缺口关闭后再处理。

建议缺口规格：

- 缺口宽度：`120px`，足够一个僵尸通过，但会产生拥挤。
- 缺口形成时间：墙体耐久归零后 `0.5s` 完成碎墙动画。
- 缺口形成后：该处不再阻挡移动和射线，墙体剩余部分继续阻挡。
- 缺口不可自动修复，也不需要玩家手动开门。
- 墙体受到攻击时显示局部裂纹和耐久条；缺口形成时发出一次明显的破墙反馈。

墙体的详细碰撞方式需要在实现时扩展当前地形模型：完整墙体阻挡移动和射线，局部缺口需要拆成可碰撞的墙段或由运行时阻挡区域表达。设计上不允许通过单位拥挤穿墙、翻墙或从四角钻出。

### 2.3 平面示意

```text

              ↓       ↓       ↓
        ┌────────────────────────────┐
        │                            │
        │        S   S   S           │
        │      S    绿人    S        │
西侧    │    S   绿人 绿人   S       │    东侧
生成区  │    S   绿人 绿人   S       │    生成区

        │        S   S   S           │

       外框：四面首尾相连的别墅墙体
```

示意图中的四面墙是一个完整矩形空间。墙内不再放置 W1–W4 等内部墙段、房间隔断、入口门或其他障碍物。外部僵尸可以从四侧接近不同墙体，玩家需要观察哪一面墙先出现裂纹，并将士兵向即将形成缺口的一侧调整。

## 3. 初始单位和站位

### 3.1 六名平民

平民统一使用绿色外观，不区分衣服颜色、职业和个人能力。为了让玩家快速判断保护目标，六名平民使用同一种绿色主体、浅绿色描边和相同的头顶标识；编号只用于调试和事件日志，不在战斗画面中显示。

平民中心点为 `(540,1170)`，六人采用紧凑六边形排布：

| 平民 | 初始位置 | 外观与状态 |
|---|---:|---|
| `civilian-1` | `(540,1080)` | 绿色主体，`Civilian` |
| `civilian-2` | `(615,1125)` | 绿色主体，`Civilian` |
| `civilian-3` | `(615,1215)` | 绿色主体，`Civilian` |
| `civilian-4` | `(540,1260)` | 绿色主体，`Civilian` |
| `civilian-5` | `(465,1215)` | 绿色主体，`Civilian` |
| `civilian-6` | `(465,1125)` | 绿色主体，`Civilian` |

平民建议半径为 `14px`，相邻中心距离约 `75px`。平民不参与碰撞推挤，士兵不能把平民推离初始保护区。平民上方只显示统一的绿色目标标记和状态，不显示个人血条，避免玩家误以为可以通过治疗或补血挽救平民。

### 3.2 七名士兵

沿用当前 7 人编成：4 名步枪兵、2 名喷火兵、1 名盾兵。士兵在场景初始化时直接生成在平民周围，不经过入口、不播放进场路线、不等待布阵阶段。

| 士兵职责 | 推荐站位 | 初始朝向 | 目的 |
|---|---:|---|---|
| 盾兵 1 名 | `(540,1400)` | 朝向南墙 | 作为南侧第一道缓冲，便于转向新缺口 |
| 喷火兵 2 名 | `(405,1170)`、`(675,1170)` | 朝向西、东墙 | 覆盖左右两侧缺口和进场通道 |
| 步枪兵 2 名 | `(450,970)`、`(630,970)` | 朝向北墙 | 观察并压制北侧缺口 |
| 步枪兵 2 名 | `(420,1420)`、`(660,1420)` | 朝向南墙 | 支援盾兵，保护平民南侧 |

这些位置是默认环形保护阵型，而不是固定编队。玩家仍然可以按现有选择半径和拖拽规则调整单个士兵；士兵离开保护圈后，平民不会自动跟随，也不会改变目标位置。所有士兵、平民和墙体都必须在别墅内部有效区域内生成。

## 4. 外部僵尸的持续生成

### 4.1 调度原则

本场景只使用一条持续生成调度，不定义波次、波次编号、波次开始时间或波次之间的等待关系。战斗钟从 `0s` 开始，生成器按照间隔逐个或小批量产生僵尸；间隔随战斗时间平滑缩短，让压力逐渐增加。

建议首轮验证配置：

| 参数 | 初始值 | 说明 |
|---|---:|---|
| 总生成上限 | `240` 只 | 达到后停止产生新的僵尸 |
| 初始生成间隔 | `1.20s` | 战斗开始时保持可观察的压力 |
| 最小生成间隔 | `0.45s` | 达到密集阶段后的下限 |
| 单次生成数量 | `1–3` 只 | 以单只为主，偶尔连续生成 2–3 只 |
| 生成方向 | 北/东/南/西各 25% 起始权重 | 按墙体耐久动态微调 |
| 首轮敌人类型 | 普通僵尸为主，少量胖僵尸 | 平民转化只生成普通僵尸 |

生成间隔按照连续曲线从 `1.20s` 逐步下降到 `0.45s`，不在某个时间点突然切换。四侧权重默认均衡；某面墙耐久低于其他墙体 `25%` 以上时，生成器只把最多 `15%` 的额外权重转移到该侧，避免所有僵尸瞬间集中到一面墙而失去观察和调整空间。

达到 `240` 只的生成上限后，调度器设置 `generationComplete=true`，不再补生成因提前死亡、转换或墙外拥堵造成的数量差异。胜利必须等生成完成且场上没有存活僵尸，同时 6 名平民均未转化。

### 4.2 四侧出生位置

僵尸出生在墙外，不能直接生成在别墅内部。每面墙外保留独立的生成区域：

| 生成点 | 区域 | 初始目标 |
|---|---|---|
| `north-outside` | `x=150..930, y=250..360` | 北墙中段附近 |
| `east-outside` | `x=990..1020, y=500..1900` | 东墙中段附近 |
| `south-outside` | `x=150..930, y=2060..2140` | 南墙中段附近 |
| `west-outside` | `x=60..90, y=500..1900` | 西墙中段附近 |

僵尸生成后先选择最近且仍完整的墙体，移动到墙外接触点并攻击墙。墙体出现缺口后，附近的僵尸切换目标为缺口，进入内部后再按照“平民优先、士兵其次”的目标规则行动。

### 4.3 僵尸目标和墙体交互

1. 墙体完整时，僵尸不能穿过墙，也不能隔墙攻击平民或士兵。
2. 僵尸接触墙体后优先攻击墙体，不因为看到墙内的平民而改变目标。
3. 墙体缺口形成后，最近的僵尸进入缺口；缺口处拥挤时允许身体重叠，但不能穿过未损坏的墙段。
4. 进入别墅后，僵尸优先寻找最近的未转化平民；若当前没有可达平民，再攻击士兵。
5. 僵尸不能绕到地图边界外侧再从墙角钻入，四面墙的外侧和四角都需要保持碰撞连续性。

## 5. 平民被攻击后的变身

### 5.1 变身状态

平民不使用普通单位的 HP 伤害模型，也不设置“受伤后还可以恢复”的阶段。僵尸对平民的第一次有效攻击命中后，立即进入 `Transforming` 状态；变身动画完成后，平民从战场移除并在同一位置生成一只普通僵尸。

建议时间线：

1. 僵尸攻击命中，平民颜色从绿色变为暗绿色并播放短暂受击闪烁。
2. `0.8s` 变身读条期间，平民保持原地，不再接受其他目标或移动逻辑。
3. 读条完成后，平民实体被替换为 `normal_zombie`，普通僵尸使用完整初始生命值和普通僵尸属性。
4. 变身完成瞬间发布 `civilian_transformed` 事件并立即判定“解救失败”；战斗钟和持续生成器停止，进入失败结算。

为了保持目标清晰，变身不会被士兵的普通伤害打断，也不会把变身后的普通僵尸计入士兵击杀或额外评分。变身后的普通僵尸主要用于表现、事件回放和调试验证；失败结算以“平民已被转化”为唯一原因。

### 5.2 可读反馈

- 平民被命中时显示绿色目标标记闪烁和“平民受到攻击”提示。
- 变身读条期间显示统一的绿色到灰绿色的渐变，不使用复杂的个人状态图标。
- 变身完成时播放一次短促的转化特效，原绿色目标标记消失，普通僵尸使用现有僵尸外观。
- HUD 的平民计数从 `6/6` 变为 `5/6` 等，并在变身完成后立即显示 `解救失败`；不继续显示其他评分信息。

## 6. 视觉设计

### 6.1 别墅和墙体

- **地面**：暖灰色或浅米色别墅庭院地面，中央区域保持干净，方便识别绿色平民。
- **四面墙**：四面使用同一套米灰色混凝土材质和连续浅色描边，四角连接处不能出现黑线或视觉缝隙。
- **墙体受损**：完整墙体显示裂纹级别，裂纹随耐久下降逐渐增加；缺口形成后显示破碎边缘和向内散落的碎片。
- **墙外区域**：比室内更暗，使用冷灰色地面和低对比度雾气，让僵尸从外部逐渐靠近时仍可辨认。

### 6.2 平民和士兵

- **平民**：全部使用同一种绿色主体、浅绿色描边和相同大小，不使用黄、白、红、蓝等区分色。
- **平民状态**：绿色表示正常，暗绿色表示变身读条，普通僵尸外观表示转化完成。
- **士兵**：沿用当前蓝色阵营色；盾兵保留白色盾面轮廓，喷火兵保留红橙色火焰，便于从绿色平民中快速区分。
- **保护圈**：中央地面显示一圈低透明度的绿色安全范围，仅用于表达平民区域，不作为额外得分或数值规则。

## 7. HUD 和结算

HUD 只展示解救目标相关的信息：

- `平民：6/6`
- `墙体状态：北 / 东 / 南 / 西`，显示完整、受损或已击穿
- `僵尸正在接近：北 / 东 / 南 / 西`，用于帮助玩家理解外部压力
- 失败文案：`平民被感染，解救失败`
- 胜利文案：`6 名平民成功获救`

不增加用时排名、击杀排行、墙体剩余耐久评分、士兵存活评分、星级、奖励倍率或其他评价条件。结算页只需要确认平民是否全部获救。

## 8. 后续实现影响

本稿不直接修改代码。实现时需要把以下内容拆成独立任务：

1. **平民实体**：新增 `civilian` 类型或独立 `CivilianStore`，至少记录 `id、position、state、active`；不套用普通士兵 HP 和移动逻辑。
2. **平民转化**：增加 `Civilian -> Transforming -> normal_zombie` 的状态迁移，提供 `civilian_transformed` 事件，转化完成立即触发失败。
3. **连续生成器**：新增不依赖 `WaveManager` 的持续调度器，支持总生成上限、连续变化的生成间隔、四侧权重和 `generationComplete` 状态。
4. **四墙连接地图**：地图只配置北、东、南、西四个首尾相连的墙体，不配置任何入口、门、内墙或房间障碍。
5. **局部破墙**：将完整墙体与运行时缺口拆分为可碰撞墙段，保证墙体仍能阻挡移动和射线，缺口允许僵尸进入。
6. **目标选择**：墙外僵尸先锁定墙体，进入室内后优先寻找未转化平民；不能隔墙攻击。
7. **胜负条件**：胜利判断为 `generationComplete && aliveZombies === 0 && civiliansRemaining === 6`；失败判断为任一 `civilian_transformed` 事件。
8. **表现层**：`MapView` 绘制连续四墙、裂纹和缺口；`HudController` 只增加平民计数、墙体状态和解救结算。

## 9. 验收标准

### 9.1 空间和初始化

- [ ] 别墅由北、东、南、西四面首尾相连的墙体组成，四角没有缺口。
- [ ] 别墅内部没有入口门、内部墙、房间隔断或额外障碍。
- [ ] 6 名平民和 7 名士兵在战斗开始时都已经位于别墅内部。
- [ ] 6 名平民集中在中央，外观统一为绿色且初始不移动。
- [ ] 7 名士兵直接环绕平民生成，玩家不需要执行进场或集合操作。

### 9.2 持续生成和墙体

- [ ] 僵尸只从四面墙外生成，不会直接生成在室内或平民附近。
- [ ] 僵尸逐渐生成，使用连续间隔和四侧权重，不存在波次编号、波次等待或波次结算。
- [ ] 完整墙体阻挡僵尸移动，僵尸先攻击墙体。
- [ ] 墙体耐久归零后只在受击位置形成缺口，缺口允许僵尸进入，剩余墙段继续阻挡。
- [ ] 僵尸进入室内后优先接近平民，不能隔墙攻击平民。

### 9.3 平民解救

- [ ] 平民不移动、不攻击、不接受玩家移动指令。
- [ ] 所有仍处于平民状态的目标都使用统一绿色外观；完成变身后按普通僵尸外观显示。
- [ ] 任意平民被僵尸有效攻击后进入变身流程，并在 `0.8s` 后变为普通僵尸。
- [ ] 任意平民完成变身时立即判定解救失败，停止连续生成并进入失败结算。
