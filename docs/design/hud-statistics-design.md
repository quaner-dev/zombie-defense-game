## 本次需求与范围

1. 战场上方独立显示当前场景名称，改善统计信息的视觉层级。
2. 战场下方第一行显示各兵种当前数量，名称和数字使用对应士兵颜色，例如“枪兵 7　喷火兵 3　狙击兵 1　盾兵 2”。
3. 兵种数量下方显示士兵、僵尸总量与实时对比条：士兵绿色在左，僵尸紫色在右，分割线和色块宽度按数量比例同步改变。

本稿记录已确认的界面设计。使用现有“大屋守卫”地形作为背景示意；本次 HUD 调整不新增场景或变更玩法参数。示例编制共 13 人，取自本次需求，不代表现有关卡的初始人数。交互稿里的地图是静态画面，调整统计数字用于评审 HUD 的版式和比例；正式界面读取本局实际兵种与存活数量。

## 布局与视觉层级

```text
┌────────────────────────────────┐
│ 大屋守卫                        │  当前场景名
│ 故事模式 · 第一幕   第2/3波 00:28 │  次级状态
├────────────────────────────────┤
│                                │
│           完整战场              │
│                                │
├────────────────────────────────┤
│ 枪兵 7  喷火兵 3  狙击兵 1  盾兵 2│  第一行；各兵种色
│ ────────────────────────────── │
│ 士兵 13                僵尸 26  │  绿色 / 紫色
│ [  绿色 33.3%  │  紫色 66.7%  ]│  实时对比条
│ 当前存活单位              · 实时│
└────────────────────────────────┘
  首页           暂停     重新开始
```

场景名是主标题，统计用一张紧凑的深色圆角面板承载。兵种数量保持一行，避免拆成多层小卡片。总量和对比条位于下一层，文字与色带保持接近，便于迅速对应。采用细描边、留白与轻微明暗差区分区域，发光主要保留在战场单位上。

模式、波次与计时为次级信息：波次场景显示实际波次；连续生成场景显示“持续防守”，不显示虚构波次或预计剩余时间。名称取当前场景的 `title`，切换场景后随之更新。

配色以当前 [drawing.ts](../../assets/scripts/adapter/drawing.ts) 中的 `soldierColors` / `palette` 为准，后续实现应复用映射。旧视觉文档中的占位配色不作为本次依据。

| 显示名称 | 单位类型 | 颜色 | 使用位置 |
|---|---|---|---|
| 枪兵 | `rifleman` | 绿 `#63D68F` | 名称、数字、色点 |
| 喷火兵 | `flamethrower` | 红 `#F04438` | 名称、数字、色点 |
| 狙击兵 | `sniper` | 蓝 `#55C5F4` | 名称、数字、色点 |
| 盾兵 | `shield` | 浅蓝 `#B9D7E8` | 名称、数字、色点 |
| 工兵机枪（出现时） | `engineer` | 橙 `#F59E0B` | 沿用同一兵种行规则 |
| 士兵阵营 | 全部存活士兵 | 绿 `#63D68F` | 士兵总数、左侧色带 |
| 僵尸阵营 | 全部存活僵尸 | 紫 `#9F8BE8` | 僵尸总数、右侧色带 |

固定展示本场已编入的兵种，顺序为枪兵、喷火兵、狙击兵、盾兵、工兵机枪。某一兵种减员至零后保留“兵种 0”，避免整行左右跳位；本场从未编入的兵种可以不显示。预览固定展示需求中的四种兵。

兵种数是该类型当前存活士兵数，士兵总量是所有兵种存活数之和。僵尸总量是当前场上存活僵尸总数，包含特殊僵尸；未生成、已死亡和累计击杀数量不计入。平民不计入士兵总量。兵种行和双方总量应读取同一份战斗快照，避免同一帧数字不一致。

## 实时比例与移动规则

令士兵存活数为 `H`，僵尸存活数为 `Z`，色带总宽度为 `W`。当 `H + Z > 0` 时：

```text
绿色宽度 = W × H / (H + Z)
紫色宽度 = W × Z / (H + Z)
分割线位置 = 色带左端 + 绿色宽度
```

| 状态 | 士兵 : 僵尸 | 绿色 / 紫色 | 可见变化 |
|---|---:|---:|---|
| 初始示例 | 13 : 26 | 33.3% / 66.7% | 分割线在全宽的三分之一处 |
| 双方相等 | 13 : 13 | 50% / 50% | 分割线居中 |
| 僵尸减少 | 13 : 3 | 81.25% / 18.75% | 相对初始向右移动，绿色扩大 |
| 士兵减员 | 4 : 26 | 13.33% / 86.67% | 相对初始向左移动，紫色扩大 |
| 僵尸清零 | 13 : 0 | 100% / 0% | 全绿，隐藏分割线 |
| 士兵清零 | 0 : 26 | 0% / 100% | 全紫，隐藏分割线 |
| 双方为零 | 0 : 0 | 无比例 | 双方数字为零，灰色底条，隐藏分割线 |

两侧始终相接，采用纯色填充。不要把分割线固定在中点，不添加会被误读成分割线的固定刻度，也不使用与占比无关的渐变。不得给少数一方强行保留最小色块宽度；即使 `1 : 999`，也保持真实的 `0.1% : 99.9%`。

数值在快照变化时直接更新，不滚动计数。绿色宽度与分割线使用相同的 `220ms ease-out` 过渡，收到新数量时从当前位置继续向新比例移动，不叠加过时动画、不弹跳。减少动态效果的系统设置下取消过渡。数字始终显示实际整数，比例计算保留精度，游戏主界面无需额外显示百分比；交互稿右侧的百分比仅供评审。

暂停时冻结战斗数据；本轮结束后保留最终统计，仍由现有结算判定胜负。僵尸暂时清零时只代表当前场上为零，不据此显示胜利或“已清场”。重开、切换场景时直接显示新初始值，不从上一局人数缓动。

## 其他场景的信息兼容

别墅场景仍保留“平民 6/6”、变身状态、门窗状况、已生成数量等保护目标信息，放在场景标题下的独立任务信息区。其信息不能替代场景名或覆盖下方兵种行。按任务区实际高度调整战场可用空间，保持完整地图可见。平民不参与绿紫比例；其变为僵尸后，以核心快照的僵尸存活数为准。

此稿展示通用统计面板；别墅任务信息区的引擎排版在接入时单独校验，保留既定保护目标和胜负规则。

## 交互稿评审方式

用浏览器直接打开 [hud-statistics-preview.html](hud-statistics-preview.html)，无需安装依赖或启动游戏。

- 点击“初始示例 / 双方相等 / 僵尸减少 / 士兵减员 / 僵尸清零 / 双方为零”，检查数字、绿紫宽度和分割线。
- 点击“播放变化”，自动展示六个数量状态；点击任意预设、输入框或滑块后停止自动演示。
- 四个士兵输入框各支持 `0–99`，僵尸输入框支持 `0–9999`；滑块用于快速调节僵尸数量。
- 将所有士兵输入设为零、僵尸保持大于零，检查全紫状态；将僵尸设为零，检查全绿状态。
- 缩窄窗口，检查预览与说明改为上下排列。按钮、输入和状态都有键盘焦点与文本标注，颜色之外保留兵种名称及数量。
