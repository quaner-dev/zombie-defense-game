# 验证与自动审核

这套验证分为两层：Node 的无渲染自动审核负责确认战斗规则、挂机结果、固定指挥和完整源码测试；Cocos Creator 负责实际场景导入和运行。两层结果不能互相替代。

## 一条命令跑完整检查

在项目根目录准备 Node.js v26.7.0、npm 和依赖后执行：

```sh
npm ci
npm run verify:mvp
```

`verify:mvp` 按顺序执行：

1. `npm run sync:core`：从 `src/core` 和 `config` 生成 Cocos 使用的核心包。
2. `npm run acceptance:report`：跑 10 个挂机种子和 1 个六命令指挥场景，写入 `docs/testing/mvp-test-report.json`。
3. `npm test`：运行核心、适配层、验收、性能和工作流测试。
4. `npm run typecheck`：检查核心 TypeScript 和测试。
5. `npm run typecheck:cocos`：检查 Cocos 适配层和真实 Creator 类型声明。
6. `npm run check:cocos-bundle`：在无 Node API 的浏览器 realm 执行核心，并检查适配包只把 `cc` 留作引擎外部依赖。

任何一项失败都会继续执行后续项目，最后命令返回非零退出码。这样既能拿到完整报告，也不会把当前战斗基准失败误报为通过。可以把报告写到临时位置，避免覆盖仓库记录：

```sh
npm run verify:mvp -- --output /tmp/zombie-defense-mvp-report.json
```

只想快速跑战斗基准时执行：

```sh
npm run acceptance:report
```

报告中的 `idle` 是挂机场景，`scripted` 是按当前六条群体命令执行的指挥场景。脚本会对结果、波次时间、生成总数、首次减员、终局和指挥选中 ID 做断言；断言失败会写出 JSON 后返回 1。它不需要 Cocos，也不等同真机性能。

## 当前版本的自动审核结果

最近一次按当前屏幕外出生配置重跑得到：挂机首次减员 **33.55 秒**，**68.65 秒**失败，剩余 **17** 只僵尸；固定六命令指挥在 **68.05 秒**胜利，剩余 **22** 名人类、**0** 只僵尸。波次仍在战斗时间 **0 / 7 / 20 秒**触发，六条命令的选中人数和 ID 校验通过。

这表示自动审核流程和当前战斗基准均已通过。后续不要只更新报告中的数字来消除失败；需要先决定是否调整出生位置、战斗参数或指挥基准，再重新跑同一套审核。

## Cocos Creator 验证

仓库目前没有经过验证的 Cocos Creator 无人值守 CLI 命令。Creator 3.8.8 的可执行验证步骤是：

1. 用 Creator Dashboard 导入项目，等待 AssetDB 完成。
2. 打开 `assets/scenes/Battle.scene`，保存一次场景，选择 Current Scene 后点击 Play。
3. 观察 50 名步枪兵、3 秒布阵、三路固定波次、中文 HUD、拖拽群体、移动目标标记、弹道、破门抖动、近战受击脉冲和终局冻结。
4. 打开 Creator 的 Console。启动日志使用 `[ZombieDefense]` 前缀，会记录 `onLoad`、布局、前几帧和重启；这些日志用于判断场景是否真正进入运行态。

`npm run check:cocos-bundle` 只验证浏览器包和场景/脚本 UUID，不验证编辑器导入、Graphics 实际渲染或微信包。真机、微信开发者工具、设备 FPS 和触控在后续单独进行。

## 调整关卡后的回归规则

- 新增关卡时，在 `config/levels.json` 增加关卡定义，使用 `BattleSession.restart(levelId)` 选择它；战斗核心不需要复制一套。
- 固定时间出怪由 `WaveManager` 管理。当前是 0/7/20 秒的固定波次；后续连续或间隔生成应替换调度器，实现同一更新和完成接口，不把生成逻辑塞进渲染层。
- 地图可在 `MapModel` 的可选 `terrain` 数据中增加墙、掩体、减速区等描述；当前只保存配置，不启用碰撞、阻挡或寻路，后续再按规则接入。
- 每次修改地图、波次或数值后，先跑 `npm run sync:core` 和 `npm run acceptance:report`，再跑 `npm test` 与两项 typecheck。
