# 页面与流程核对记录（2026-10-17 MVP讨论稿）

> 历史范围说明：本文记录 2026-10-17 的单关 MVP 决定。现已增加故事/演练入口、选关、小屋→大楼楼下推进和矩形建筑墙体；当前流程以 [故事与场景设计稿](10-story-scenes-design.md) 和源码为准。下文“无菜单、仅一关、未启用墙体”等历史结论不再代表当前版本。

核对日期：2026-10-17  
核对范围：当前 `Battle` 场景、HUD、输入、战斗核心、自动验收脚本和项目文档。

## 结论

当前实现使用一个通用 `Battle` 场景承载模式入口、故事/场景选择、战斗和结算。故事模式从小屋推进到大楼楼下，场景演练可单独选择任一地图；每个场景均为三波，并使用 7 人小队。成长和跨会话进度保存仍未实现。

项目现在有可执行的无渲染验证入口：

```sh
npm ci
npm run verify:mvp
```

这条命令会同步核心、跑挂机和固定指挥验收、写出 JSON 报告、跑完整测试、做两项 TypeScript 检查和 Cocos bundle 合约检查。Cocos Creator 3.8.8 的实际导入、预览和构建仍需要 Creator 环境；真机验收按后续安排进行，不作为本轮缺陷展开。

本轮场景自动模拟结果见验证记录：

- 挂机：首次减员 **45.40 秒**，**56.95 秒**失败，剩余 **303** 只僵尸。
- 开局微操喷火兵与盾兵：首次减员 **44.30 秒**，**89.25 秒**胜利，**6** 名人类存活。
- 小屋生成 **700** 只，楼下生成 **270** 只；故事流程两关模拟均胜利。

详细命令和事件证据见 [验证与自动审核](验证与自动审核.md) 及 [验收报告](testing/mvp-test-report.json)。

## 当前不作为缺陷的范围

- 故事/演练入口、场景选择与两关流程已实现；每关 3 秒布阵不可跳过。
- 新手引导、独立结算页、暂停/开始细化、成长、关卡选择、存档和音效均不属于本轮验收范围。
- AI 自动选择攻击目标；白色准星只作显示，不支持玩家手动集火。
- 僵尸从出生起选择可达目标；沿墙绕行，并优先攻击挡路的关闭房门。
- 小屋走廊出生与楼下四边出生、固定时间分批出怪是当前场景规则。

## 建议讨论顺序

1. 有 Node/npm 环境后重跑自动化，并调查验收文件的文件级失败。
2. 在 Creator 3.8.8 中检查故事流程、走廊房门、火焰效果、墙角绕行和中文布局。
3. Web Mobile、微信构建、手机触控、性能与视觉结果单独记录；无渲染模拟不替代这些验收。
4. 后续 MPV 与上下车玩法放入新场景设计，不纳入当前两关。

本稿只归纳当前实现、MVP 明确排除项和后续验证缺口；不代表本轮要扩展产品范围，也没有降低玩法、配置或自动测试门槛。
