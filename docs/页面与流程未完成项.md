# 小程序页面与流程未完成项（MVP 讨论稿）

核对日期：2026-10-17  
核对范围：当前 `Battle` 场景、HUD、输入、战斗核心、自动验收脚本和项目文档。

## 结论

当前版本是“打开即开局”的单关战斗 MVP：仓库只有 `Battle` 场景，运行时动态创建战场和 HUD；打开场景后自动进入 3 秒布阵，随后开始固定三波战斗。主菜单、新手引导、独立结算页、关卡选择、成长和进度保存均明确排除在本轮范围外。

项目现在有可执行的无渲染验证入口：

```sh
npm ci
npm run verify:mvp
```

这条命令会同步核心、跑挂机和固定指挥验收、写出 JSON 报告、跑完整测试、做两项 TypeScript 检查和 Cocos bundle 合约检查。Cocos Creator 3.8.8 的实际导入、预览和构建仍需要 Creator 环境；真机验收按后续安排进行，不作为本轮缺陷展开。

当前自动验收基准已经按屏幕外出生配置重新复测：

- 挂机：首次减员 **33.55 秒**，**68.65 秒**失败，剩余 **17** 只僵尸。
- 固定指挥：在 **28 秒 / 52 秒**执行两阶段六条群体命令，**68.05 秒**胜利，**22** 名人类存活。
- 六条命令均捕获到正确的存活单位 ID；波次在战斗时间 **0 / 7 / 20 秒**按固定时间触发。

详细命令和事件证据见 [验证与自动审核](验证与自动审核.md) 及 [验收报告](testing/mvp-test-report.json)。

## 当前页面与流程

| 阶段 | 当前实现 | 代码依据 |
|---|---|---|
| 进入游戏 | 打开 `Battle.scene` 后立即初始化并进入布阵，没有开始页 | [BattleSceneController](../assets/scripts/adapter/BattleSceneController.ts)、`assets/scenes/Battle.scene` |
| 布阵 | 自动倒数 3 秒，之后进入战斗；没有跳过按钮 | [BattleSession](../src/adapter/BattleSession.ts)、[HUD](../assets/scripts/adapter/HudController.ts) |
| 战斗 | 固定三波；按住附近至少两名士兵并拖动下令；士兵自动攻击，僵尸自动索敌 | [InputManager](../assets/scripts/adapter/InputManager.ts)、[WaveManager](../src/core/WaveManager.ts) |
| 暂停/后台 | 代码提供暂停和后台恢复，但本轮不把暂停/开始菜单作为验收目标 | [BattleSceneController](../assets/scripts/adapter/BattleSceneController.ts)、[HudController](../assets/scripts/adapter/HudController.ts) |
| 结局 | 战斗画面内显示胜负、用时、存活人数、剩余僵尸和重新开始按钮 | [ResultSystem](../src/core/ResultSystem.ts)、[HudController](../assets/scripts/adapter/HudController.ts) |

## 当前不作为缺陷的范围

- 打开即进入战斗场景；3 秒布阵不可跳过，是已确认的 MVP 规则。
- 新手引导、独立结算页、暂停/开始细化、成长、关卡选择、存档和音效均不属于本轮验收范围。
- AI 自动选择攻击目标；白色准星只作显示，不支持玩家手动集火。
- 僵尸从出生起全场选择最近目标并直线追击；当前不启用墙体阻挡和复杂寻路。
- 当前固定时间波次是有意选择；后续出怪方式通过调度接口扩展。

## 建议讨论顺序

1. 当前 MVP 范围已定为“打开即开局的单关战斗原型”，不再为主菜单、教学或独立结算页扩展需求。
2. 后续改动统一先跑 `npm run verify:mvp`，用当前挂机与指挥报告判断是否引入战斗回归。
3. 具备 Creator 后确认中文字体、Graphics 动效和场景导入；真机验收按后续计划单独记录，不在本轮展开。
4. 新增关卡时沿用现有 `levelId`、地图注册、波次调度和 `terrain` 扩展接口，保持核心与表现层解耦。

本稿只归纳当前实现、MVP 明确排除项和后续验证缺口；不代表本轮要扩展产品范围，也没有降低玩法、配置或自动测试门槛。
