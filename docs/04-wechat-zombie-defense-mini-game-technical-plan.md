# 微信小游戏技术方案（终版 v1.0）

> 历史技术方案：本文保留早期目标架构和平台规划。当前战斗核心、适配层与场景规则以 [实际架构](architecture.md) 和 [故事场景](10-story-scenes-design.md) 为准；Creator 导入、平台构建和设备表现仍待人工验证。

> 阅读提示：本文是保留的目标技术方案，不是已实现功能清单或平台验收报告。当前模块、50ms 每步索敌、SHOW_ALL、生成包边界见 [实际架构](architecture.md)；本文后续旧的 0.5s 索敌/工程树等描述不作为当前运行事实。存档、主菜单及完整设备性能目标尚未交付或验证，见 [发布清单](release-checklist.md)。

> 平台：**微信小游戏（game 类目，已确认）** · 单机 · 竖屏
> 技术栈：**Cocos Creator 3.x 框架**（组件化/ECS 解耦，非原生裸写）
> 核心目标：**丝滑度 60fps**（复刻原作 1080×2400-60fps 观感），并建立可测试、可验收的性能保障
> 状态：**终版**

---

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **Cocos Creator 3.x** | 组件+ECS 解耦、场景编辑器、资源管线、性能分析内置，满足"依赖框架、后期扩展"诉求 |
| 渲染 | Cocos 内置渲染（WebGL/2D 合批） | 批量圆点自动合批，帧率稳定性有引擎保障 |
| 游戏循环 | Cocos 组件生命周期（update/director） | 不手写 GameLoop，逻辑与渲染由引擎调度 |
| UI | Cocos UI（Label/Sprite） | 与战斗场景同引擎，HUD 数据驱动 |
| 存储 | wx.setStorageSync（引擎适配层调用） | 存档/解锁/设置 |
| 音频 | Cocos AudioSource / wx 音频 | 初版可后补 |
| 构建发布 | Cocos 微信小游戏一键构建 | 免手工适配 |

> 选 Cocos 的理由（对齐用户诉求）：
> 1. **解耦**：场景/组件/资源三层分离，新增兵种=新组件+新配置，不侵入现有代码；
> 2. **扩展**：多地图/多兵种/随机事件 = 数据+预制体组合，框架原生支持；
> 3. **丝滑**：合批渲染 + 帧率统计 + Profile 工具，性能可测可调。

## 2. 项目结构（Cocos 工程）

```
assets/
├── scenes/
│   ├── MainMenu.scene      # 主菜单
│   ├── Battle.scene        # 战斗场景（核心）
│   └── Result.scene        # 结算
├── scripts/
│   ├── core/
│   │   ├── GameManager.ts      # 全局状态（单例，场景间传递）
│   │   ├── EventBus.ts         # 事件总线（指令/波次/胜负解耦）
│   │   ├── UnitManager.ts      # 单位管理（生成/回收/查询）
│   │   ├── WaveManager.ts      # 波次管理（数据表驱动）
│   │   ├── InputManager.ts     # 触屏手势（兵群点选/拖拽）
│   │   ├── CombatSystem.ts     # 索敌/伤害/死亡
│   │   ├── MapManager.ts        # 地图路线/出生点/防线/坐标转换
│   ├── units/
│   │   ├── UnitBase.ts         # 单位组件基类（HP/属性/状态）
│   │   ├── Rifleman.ts         # 步枪兵组件（继承 UnitBase）
│   │   └── Zombie.ts           # 僵尸组件（继承 UnitBase）
│   ├── ui/
│   │   ├── HUDController.ts    # 底部信息条/进度条
│   │   └── CommandArrow.ts     # 移动方向箭头（§视觉05）
│   ├── combat/
│   │   └── ProjectileSystem.ts  # 子弹轨迹对象池和命中事件
│   └── perf/
│       ├── FpsMonitor.ts       # 帧率监控（真机可开）
│       └── PerfBudget.ts       # 性能预算断言（超限告警）
├── prefabs/
│   ├── Rifleman.prefab         # 人类圆点预制体（光晕+亮芯）
│   └── Zombie.prefab           # 僵尸圆点预制体
├── resources/
│   └── config/
│       ├── units.json          # 兵种属性
│       ├── levels.json          # 关卡/波次表
│       └── balance.json         # 平衡参数（含索敌和攻击参数）
└── textures/                   # 圆点/光晕/墙面图集
```

> 关键解耦点：`units.json` 定义兵种 → 预制体挂对应组件 → 波次表引用兵种ID → 新增内容零改代码。

## 3. 战斗流程（Cocos 生命周期）

```
场景加载 → GameManager 读关卡配置 → 部署单位（预制体实例化）
→ 每帧 update()：Input → CommandSystem 解析 → 单位行为(索敌/移动/攻击) → Projectile 表现/命中 → Combat 结算 → Wave 判定 → 胜负
→ 渲染由引擎完成（自动合批）→ HUD 数据驱动刷新
```

- 时间推进：引擎 `update` 按帧驱动；逻辑使用 `deltaTime` clamp（防低帧率跳变），不在 MVP 中引入独立固定步长模拟；
- 渲染与逻辑分离：引擎保证，逻辑不依赖帧率；子弹轨迹由表现对象池驱动，伤害仍由 `CombatSystem` 统一结算。

## 4. 触屏指挥交互实现

### 4.1 手势识别（InputManager，基于引擎触摸事件）

| 手势 | 识别逻辑 | 产出指令 |
|---|---|---|
| 单指 tap（<200ms 位移<8px） | 点到兵→选中 | Select |
| 单指拖拽（起手兵群） | 选中该处兵群 → 拖出移动路径箭头 | MoveTo（目标点） |
- 单指拖拽（起手空白） | MVP 不启用 | 不产生指令 |
- 双指 | MVP 不启用 | 完整竖屏战场固定可视 |

**布阵和战斗阶段**：单指按下即选中该点附近兵群（无需先框选、无需选择单兵），拖到目标位置松手移动；支持连续多次调整。MVP 不启用双指相机。

> 集火不占用手势：由 `CombatSystem` AI 自动决策，玩家无集火操作。
> MVP AI 集火：静止步枪兵按距离最近选择射程内普通僵尸，按 0.5s 间隔重评估（数值详见 `08-combat-numeric-model.md`）。

### 4.2 关键实现点

- 点选：点击点半径 72px 内选中附近整个兵群；不做单兵选择和空白框选；
- 移动指令：选中后拖拽 → 渲染"起点→当前点"虚线+三角箭头（规范见视觉05 §5），松手提交，拖回取消；
- 防误触：tap/drag 位移阈值 8px；指令冷却 300ms；
- 反馈：选中亮青环、移动脚下小箭头、子弹轨迹和命中亮点；MVP 不提供可点击的手动集火准星。

## 5. 丝滑度目标（60fps 保障）【核心章节】

### 5.1 目标基线

| 指标 | 目标 | 对照 |
|---|---|---|
| 帧率 | **稳定 60fps**（低端机≥50） | 原作 60fps 视频 |
| 单帧耗时 | ≤16.6ms（目标预算 12ms） | 留余量 |
| 触控延迟 | 指令下达→画面响应 ≤ 100ms | 手指跟手 |
| 卡顿 | 无 >200ms 的掉帧尖峰 | 可感知卡顿=0 |

### 5.2 帧预算分解（12ms 总预算）

| 模块 | 预算 | 手段 |
|---|---|---|
| 逻辑（单位行为/索敌） | 4ms | 空间网格 O(1) 索敌、对象池复用 |
| 渲染（合批绘制） | 6ms | Cocos 合批、图集、圆点低开销 |
| 输入+UI | 2ms | 指令队列批处理、HUD 数据驱动 |

### 5.3 性能保障手段

| 手段 | 说明 |
|---|---|
| 对象池 | 单位/弹道复用，僵尸死亡高频不触发 GC 卡顿 |
| 空间网格 | 索敌按网格查，不遍历全量（400实体仍稳） |
| 图集+合批 | 圆点/光晕/墙面合成一张图集，单批次绘制 |
| 距离裁剪 | 战场外/屏幕外单位不渲染（逻辑仍全量） |
| 预制体复用 | 波次刷怪用池化实例化，不反复 new/destroy |
| 预算断言 | `PerfBudget.ts` 超预算打日志告警，开发期即发现 |

### 5.4 丝滑度测试与验收（按目标开发）

| 阶段 | 测试方式 | 验收标准 |
|---|---|---|
| 开发期 | 模拟器 + 真机预览开 FPS 面板，每完成一模块跑一次 | 战斗中实时 FPS ≥58 |
| 压测 | 构造峰值：第3波 200 僵尸 + 满编50兵 + 连续指令 | 帧率不掉、无 >200ms 尖峰 |
| 真机矩阵 | 低端安卓（骁龙6系）+ 中端 + iPhone | 低端机 FPS ≥50，中高端 60 |
| 手感对比 | 录屏逐帧对比原作视频节奏（42s 对局） | 观感一致：移动/击杀/破门无迟滞 |
| 回归 | 每轮改版后跑自动化冒烟（挂机通关×3） | FPS 记录入档，对比上轮无劣化 |

**验收结论记录**：每次测试输出 `perf_report`（帧率曲线截图 + 平均/最低 FPS + 尖峰次数），作为"丝滑度达成"的证据存档。

## 8. 里程碑（开发计划）

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| M1 核心闭环 | 开局布阵（点哪移哪）、三路地图、单位移动/攻击、子弹轨迹、固定时间波次、胜负结算 | 挂机复刻原作节奏 + **丝滑基线通过**（§5.4 开发期项） |
| M2 指挥打磨 | AI自动集火、破门、方向箭头、防误触 | 真人试玩手感 + 压测帧率达标 |
| M3 内容补全 | 教学、简单结算、存档、菜单 | 完整一局可玩 |
| M4 扩展预留 | 随机事件、兵种解锁、多地图 | 数据驱动跑通 + 全机型回归 |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 真机性能不达标（尤其低端机） | 预算断言提前暴露；降级链：合批→距离裁剪→降分辨率渲染→降帧采样 |
| 框架学习成本 | Cocos 官方文档+编辑器可视化，降低裸写成本 |
| 触控误触毁体验 | 阈值区分 tap/drag、指令冷却、可取消 |
| 原作数值难复刻 | 挂机测试对照基线，参数全进 JSON |
| AI 集火不聪明导致崩盘 | 威胁优先级进 balance.json 可调，挂机回归观察 |

> 形态已确认：微信小游戏（game 类目），Cocos 官方支持一键构建，无需小程序降级方案。MVP 详细验收见 `09-mvp-acceptance-and-automation.md`。
