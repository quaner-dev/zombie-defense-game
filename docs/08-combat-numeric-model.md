# 战斗与数值模型（MVP v1.0）

> 目的：提供可直接实现、可重复测试的默认战斗规则。
> 单位设计和状态边界见 `07-unit-design.md`。
> 原则：先保证实时群体指挥和原作压力节奏，再通过配置调平衡。

## 1. 默认单位数值

| 属性 | 步枪兵 | 普通僵尸 |
|---|---:|---:|
| `max_hp` | 100 | 40 |
| `damage` | 10 | 10 |
| `attack_interval_s` | 0.5 | 0.13 |
| `attack_range_px` | 400 | 28 |
| `move_speed_px_s` | 120 | 41.9 |
| `collision_radius_px` | 7 | 8 |
| `target_limit` | 1 | 1 |

- 步枪兵理论射速为每秒 2 发，单发伤害 10。
- 普通僵尸按累计 0.13 秒间隔进行一次近身攻击；单次系统更新最多一次。
- 初版攻击伤害不使用随机数，不产生暴击，不使用护甲。

## 2. 时间与更新

- 客户端可由引擎 `update(deltaTime)` 驱动；当前实现为确定性 headless harness。
- Combat 单次 `deltaTime` 限制在 `0..0.05s`；harness 的 `advance(seconds)` 细分完整时长到战斗钟 50ms 边界，不丢弃超出 50ms 的时间。
- 攻击计时器使用累计时间，达到攻击间隔后执行一次攻击并扣除一个间隔。
- 单帧最多处理一次同一单位的攻击，避免低帧时瞬间连击。
- `CombatSystem` 唯一负责伤害与死亡；`ResultSystem` 在 Combat → 人类移动 → 子弹到达 → 波次之后判定胜负。死亡即时排除行为，回收不必发生在同一帧。

## 3. 步枪兵索敌与攻击

1. 仅 `Idle` 或 `Aiming` 状态的步枪兵可以攻击。
2. 查询攻击范围内所有存活普通僵尸。
3. 目标按“距离最近”排序；距离相同按 `unit_id` 稳定排序。
4. 目标无效、死亡或离开射程时重新索敌。
5. 到达攻击间隔后创建一条子弹轨迹，轨迹命中后才提交伤害事件。
6. 步枪兵移动状态不索敌、不发射子弹；移动结束后重新开始索敌。

## 4. 子弹轨迹

子弹是表现对象，不是独立战斗单位，不参与碰撞查询和单位数量统计。

### 发射与命中

- 发射点：步枪兵当前地图坐标。
- 目标点：发射瞬间目标的当前坐标。
- 轨迹：从发射点到目标点的直线插值。
- 飞行速度：`900px/s`。
- 最大飞行时间：`0.35s`。
- 命中判定：到达目标点，或飞行时间达到最大值时命中。
- 命中时再次确认目标仍存活；若目标已死亡，子弹只播放到达效果，不产生伤害。
- 子弹表现建议使用对象池、短线段或细小精灵，颜色为柔和亮白/浅青。
- 同一发子弹只产生一次命中事件。

### 轨迹视觉

- 普通子弹轨迹持续约 `0.05~0.12s`，不要使用瞬时连线代替。
- 起点到目标点可有轻微透明度衰减，命中时显示小型亮点。
- 子弹轨迹不应遮挡单位主体；渲染层低于 HUD、高于单位或作为单位子层。
- 子弹池容量建议初始 `64`，达到上限时优先回收最早完成的表现对象，不影响伤害事件。

## 5. 僵尸移动与近身攻击

1. 僵尸从对应出生区域生成后即直线追击全场最近士兵。
2. `position.y >= defense_line_y` 时标记为 `Breached`，只触发一次破门事件。
3. 每个逻辑步查询全场最近存活士兵，与跨线状态无关。
4. 僵尸与目标距离 `<= 28px` 时停止移动并进入 `Attacking`。
5. 达到累计 `0.13s` 攻击间隔后直接对目标扣除 10 HP。
6. 目标死亡或距离超过范围时重新选择目标并继续移动。
7. 破门不增加僵尸移速，不降低人类防御，不叠加额外伤害。

## 6. 群体移动

- 玩家指令选择点击点半径 `72px` 内、且未死亡的步枪兵。
- 一次指令产生一个 `MoveGroupCommand`，包含单位 ID 列表、目标点和发出时间。
- 每个单位向目标点附近的稳定编队位置移动，避免所有单位重叠在同一点。
- 移动速度使用单位 `move_speed_px_s`；到达距离 `<= 12px` 时视为到达。
- 新指令覆盖旧指令；移动中的单位不攻击。
- 无法选择到单位时不产生指令，也不改变当前战斗状态。

## 7. 胜负规则

- 所有波次均已生成且存活僵尸数为 0：胜利。
- 存活步枪兵数为 0：失败。
- 同一帧同时满足两者时，优先判定失败，避免玩家全灭后显示胜利。
- 结算触发后停止生成、移动、攻击和伤害，保留结算界面需要的统计快照。

## 9. 首轮调参顺序

1. 先调僵尸生命值和步枪兵射程，使前两波在挂机时基本无损。
2. 再调僵尸移速和防线距离，使第 3 波在约 25~35 秒开始造成减员。
3. 最后调僵尸近身攻击间隔和伤害，使挂机在约 38~50 秒内失败。
4. 子弹速度只影响观感和响应，不用于弥补战斗数值问题。

## MVP follow-up：当前规则与校准

A/B/C、左中右仅为出生区域和统计标签，不是固定路径。僵尸出生即在全场选择最近存活士兵，每个 50ms 逻辑步重新决策，同距按稳定 ID；无障碍空间内直线追击，未实现 A*、导航网格或绕墙。距离 <=28px 即可近战，防线 y=1200 只记录首次跨线警告，不是伤害门槛，也不改变速度、伤害或防御；追击可返回线上方。

当前配置采用 probe3 的完整配对：僵尸速度 **41.9px/s**、攻击间隔 **0.13s**。间隔从 0.25→0.13s 是现有参数的平衡校准，不是新增机制；50ms 固定步上累计攻击时间，单步最多一次。HP40、单次伤害10、步枪HP100/伤害10/射程400/间隔0.5s/速度120、弹速900/寿命0.35s 均未改；九列5px出生布局、50人、350僵尸和0/7/20s波次保留。

当前实测：挂机种子1..10首次减员 **25.7s**，**49.55s失败，0人/57僵尸**；指挥 **53.85s** 首次减员，**74.85s胜利，4人/0僵尸**。使用六条正常群体命令：战斗24s按A/B/C当前活兵质心选择，分别到(180,1550)/(540,1550)/(900,1550)；35s重新捕获当前活兵质心与ID，再分别到(180,1750)/(540,1750)/(900,1750)。两阶段实际选择17/17/16人；没有隐藏加伤、增兵或特殊胜利。旧30.30s/47.75s/69与78.30s/3仅为线后追击历史，当前报告已替换，不再作为当前精确预言。25..35s首次减员、38..50s挂机失败、指挥胜利且存活>0及完整快照/单位/事件分段等价仍是硬目标。

MVP强制3秒自动布阵，无跳过入口；endDeployment仅为内部测试工具。可选微信短振动已实现，同批跨线合并且至少1000ms限频；无能力/抛错/异步失败不阻断战斗，暂停后台不补播、重开重置，物理效果未验证。墙侧阴影与复杂场景经用户确认延期；不扩展其他视觉功能。卡顿策略暂保留，待用户Cocos反馈再决定。Creator导入/真实渲染/构建、手机触控/振动/FPS/内存仍待用户手测，GitHub/许可证/发布暂缓。
