# 战斗与数值模型（MVP 当前配置）

> 目的：提供可直接实现、可重复测试的默认战斗规则。
> 单位设计和状态边界见 `07-unit-design.md`。
> 原则：先保证实时群体指挥和原作压力节奏，再通过配置调平衡。

## 1. 默认单位数值

| 属性 | 步枪兵 | 喷火兵 | 盾兵 | 普通僵尸 |
|---|---:|---:|---:|---:|
| `hitPoints` | 100 | 110 | 220 | 60 |
| `damagePerHit` | 30 | 24 | 20 | 10 |
| `attack_interval_s` | 0.35 | 0.6 | 0.5 | 0.13 |
| `attack_range_px` | 260 | 190 | 220 | 28 |
| `speed_px_per_s` | 48 | 44 | 40 | 41.9 |
| `diameter_px` | 28 | 30 | 34 | 32 |
| `area_radius_px` | - | 72 | - | - |

- 步枪兵每 0.35 秒一发，理论射速约每秒 2.86 发，单发伤害 30；普通僵尸 60 HP，需要 2 次有效命中。
- 普通僵尸按累计 0.13 秒间隔进行一次近身攻击；单次系统更新最多一次。
- 初版攻击伤害不使用随机数，不产生暴击，不使用护甲。
- 喷火兵在 190px 内沿火焰轨迹攻击；命中点周围 72px 内的僵尸各受 24 点伤害。
- 当前小队为 4 名步枪兵、2 名喷火兵和 1 名盾兵，共 7 人。

## 2. 时间与更新

- 客户端可由引擎 `update(deltaTime)` 驱动；当前实现为确定性 headless harness。
- Combat 单次 `deltaTime` 限制在 `0..0.05s`；harness 的 `advance(seconds)` 细分完整时长到战斗钟 50ms 边界，不丢弃超出 50ms 的时间。
- 攻击计时器使用累计时间，达到攻击间隔后执行一次攻击并扣除一个间隔。
- 单帧最多处理一次同一单位的攻击，避免低帧时瞬间连击。
- `CombatSystem` 唯一负责伤害与死亡；`ResultSystem` 在 Combat → 人类移动 → 子弹到达 → 波次之后判定胜负。死亡即时排除行为，回收不必发生在同一帧。

## 3. 步枪兵索敌与攻击

1. `Idle`、`Moving` 或 `Aiming` 状态的步枪兵可以攻击。
2. 查询攻击范围内、与士兵之间没有墙体遮挡的存活普通僵尸。
3. 目标按“距离最近”排序；距离相同按 `unit_id` 稳定排序。
4. 目标无效、死亡或离开射程时重新索敌。
5. 到达攻击间隔后创建一条子弹轨迹，轨迹命中后才提交伤害事件。
6. 移动不会暂停索敌与射击；移动结束后继续自动索敌。

## 4. 子弹轨迹

子弹不是独立战斗单位，不计入单位数量。核心维护飞行位置并检查墙体碰撞，表现层根据事件绘制，不自行决定伤害。

### 发射与命中

- 发射点：步枪兵当前地图坐标。
- 目标点：发射瞬间目标的当前坐标。
- 轨迹：从发射点到目标点的直线插值。
- 飞行速度：`900px/s`。
- 最大飞行时间：`0.35s`。
- 每次更新对前后位置之间的整段轨迹检测墙体，薄墙和大时间步也会停在首次接触点；碰墙产生 `projectile_blocked` 与 `projectile_expired`，不产生目标伤害。
- 正常到达目标点时结算一次；保留最大寿命到期的结算规则。当前 260px 射程小于 315px 最大飞行距离，正常射击会在寿命结束前到达。
- 到达时再次确认目标仍存活，并检查发射点、到达点至目标当前位置的墙体遮挡；目标途中躲到墙后或已死亡时只播放原落点效果，不产生伤害。
- 使用共享 Graphics 绘制浅金色飞行线和亮白弹头，不为每发子弹创建 Node。
- 同一发子弹只产生一次命中事件。

### 轨迹视觉

- 枪口闪光持续 `0.08s`；飞行中显示起点到当前位置的淡线、最长 `44px` 的明亮尾迹和弹头，不提前连接到目标。
- 命中后整段已飞过的轨迹保留 `0.10s` 并淡出，确保同一帧发射并命中的近距离子弹也有可见弹道。
- 命中闪光持续 `0.12s`；墙面接触显示暖色火花，轨迹末端固定在墙面。
- 子弹轨迹不应遮挡单位主体；渲染层低于 HUD、高于单位或作为单位子层。
- 每帧按游戏时间清理过期弹道、枪口与命中效果；终局和重启清空所有临时效果，不影响伤害事件。

## 5. 僵尸移动与近身攻击

1. 僵尸出生后每个 50ms 逻辑步重新选择最近的可达存活士兵；距离相同时按稳定 ID 排序。
2. 无墙阻挡时直线追击；墙体遮挡时沿墙角可见图寻找路径。不可达目标会被其他可达士兵替代，贴墙目标使用可行走接近点。
3. 小屋中，挡住目标路线的关闭房门是可攻击地形。僵尸先攻击门，门的 600 HP 耗尽后才可穿过门洞进入房间；普通墙不会被近战伤害。
4. 楼下场景没有房门，僵尸沿建筑外侧和街道通道绕行。
5. 僵尸与目标距离 `<= 28px` 且没有墙体或房门阻挡时进入 `Attacking`，按自身配置的累计攻击间隔和伤害值结算。
6. 目标死亡、不可达或离开近战范围后重新选取目标并移动。越过 `defense_line_y` 只产生一次警告标记，不限制追击方向，也不改变伤害。

## 6. 群体移动

- 玩家指令选择点击点固定半径 `112px` 内距离最近、且未死亡的一名士兵。
- 一次指令产生一个 `MoveGroupCommand`，包含单位 ID 列表、目标点和发出时间。
- 每个单位向目标点附近的稳定编队位置移动，避免所有单位重叠在同一点。
- 移动速度使用单位 `move_speed_px_s`；到达距离 `<= 12px` 时视为到达。
- 新指令覆盖旧指令；移动中的单位继续自动索敌和攻击。
- 无法选择到单位时不产生指令，也不改变当前战斗状态。

## 7. 胜负规则

- 所有波次均已生成且存活僵尸数为 0：胜利。
- 存活士兵数为 0：失败。
- 同一帧同时满足两者时，优先判定失败，避免玩家全灭后显示胜利。
- 结算触发后停止生成、移动、攻击和伤害，保留结算界面需要的统计快照。

## 8. 推荐配置结构

```json
{
  "rifleman": { "hitPoints": 100, "damagePerHit": 30, "attack_interval_s": 0.35, "attack_range_px": 260, "speed_px_per_s": 48 },
  "flamethrower": { "hitPoints": 110, "damagePerHit": 24, "attack_interval_s": 0.6, "attack_range_px": 190, "area_radius_px": 72 },
  "shield": { "hitPoints": 220, "damagePerHit": 20, "attack_interval_s": 0.5, "attack_range_px": 220, "speed_px_per_s": 40 },
  "normal_zombie": { "hitPoints": 60, "damagePerHit": 10, "attack_interval_s": 0.13, "attack_range_px": 28, "speed_px_per_s": 41.9 }
}
```

实际字段和值以 `config/units.json` 为准；场景人数、墙门和波次配置分别见 `config/scenes/cabin.json` 与 `config/scenes/courtyard.json`。

## 9. 首轮调参顺序

1. 先调僵尸生命值和士兵射程，使分批出怪的前几批在挂机时保持可读的接敌节奏。
2. 再调僵尸移速和防线距离，使三波分批进入后仍有足够反应时间。
3. 最后调僵尸近身攻击间隔和伤害，使挂机与微操的胜负差异符合当前关卡目标。
4. 子弹速度只影响观感和响应，不用于弥补战斗数值问题。

## MVP follow-up：当前规则与校准

A/B/C 是统计标签，不是固定路线。僵尸沿墙角路径绕行，走廊与房间之间的四扇门各有 600 HP；挡住路线时先破门，再进入房间。墙边达到三只时仍可堆叠翻越，翻越期间不施加单位分离推力。距离 `<=28px` 且墙体不阻挡时可近战，防线 `y=1200` 只记录首次跨线警告，不是伤害门槛。

当前配置：7 名士兵（4 步枪兵、2 喷火兵、1 盾兵）。步枪兵为 100 HP、48px/s、260px 射程、0.35s 间隔和 30 点单发伤害；喷火兵为 110 HP、44px/s、190px 射程、72px 范围、0.6s 间隔和 24 点范围伤害；盾兵为 220 HP、40px/s、220px 射程、0.5s 间隔和 20 点伤害。普通僵尸为 60 HP、41.9px/s、28px 攻击距离、0.13s 间隔和 10 点伤害。步枪与喷火单位移动中仍可攻击。

小屋从南北走廊两端生成 100/200/400 只，总计 700 只；楼下从北南东西四边生成 60/90/120 只，总计 270 只。两场景波次间隔分别为 0/7/20s 和 0/14/30s，均每批 10 只、间隔 0.5s。波次不会等待前一波清场。50ms 固定步进累计攻击时间，单步最多一次。枪弹整段轨迹碰墙即停止，到达时再次检查目标是否仍存活且无遮挡。单兵选取范围为按下点 112px 圆内的最近士兵，向松手点附近的个人落点靠拢。

当前机器实测见 [本轮验证记录](testing/scenes-test-report.md)，用 `npm run acceptance:report -- --output dist/reports/mvp-test-report.json` 可重生 JSON；已保存的 [旧验收报告](testing/mvp-test-report.json) 以及此前 15 人、350/135 只的模拟结果属于历史数据，不用作当前人数、难度或胜负基准。

MVP 强制 3 秒自动布阵，无跳过入口；`endDeployment` 仅为内部测试工具。可选微信短振动已实现，同批跨线合并且至少 1000ms 限频；无能力、抛错或异步失败不阻断战斗，暂停后台不补播、重开重置，物理效果未验证。Creator 导入、真实 Graphics 绘制、构建、手机触控/振动/FPS/内存仍待用户手测。

当前机器数据见 [验收报告](testing/mvp-test-report.json)，人工检查与填写模板见 [Cocos手测](testing/cocos-manual-checklist.md)。原作OCR保留为历史设计参考，不是本项目测量。
