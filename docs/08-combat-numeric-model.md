# 战斗与数值模型（MVP v1.0）

> 目的：提供可直接实现、可重复测试的默认战斗规则。
> 单位设计和状态边界见 `07-unit-design.md`。
> 原则：先保证实时群体指挥和原作压力节奏，再通过配置调平衡。

## 1. 默认单位数值

| 属性 | 步枪兵 | 普通僵尸 |
|---|---:|---:|
| `max_hp` | 100 | 60 |
| `damage` | 30 | 10 |
| `attack_interval_s` | 0.35 | 0.13 |
| `attack_range_px` | 260 | 28 |
| `move_speed_px_s` | 48 | 41.9 |
| `display_diameter_px` | 28 | 32 |
| `target_limit` | 1 | 1 |

- 步枪兵每 0.35 秒一发，理论射速约每秒 2.86 发，单发伤害 30；普通僵尸 60 HP，需要 2 次有效命中。
- 普通僵尸按累计 0.13 秒间隔进行一次近身攻击；单次系统更新最多一次。
- 初版攻击伤害不使用随机数，不产生暴击，不使用护甲。

## 2. 时间与更新

- 客户端可由引擎 `update(deltaTime)` 驱动；当前实现为确定性 headless harness。
- Combat 单次 `deltaTime` 限制在 `0..0.05s`；harness 的 `advance(seconds)` 细分完整时长到战斗钟 50ms 边界，不丢弃超出 50ms 的时间。
- 攻击计时器使用累计时间，达到攻击间隔后执行一次攻击并扣除一个间隔。
- 单帧最多处理一次同一单位的攻击，避免低帧时瞬间连击。
- `CombatSystem` 唯一负责伤害与死亡；`ResultSystem` 在 Combat → 人类移动 → 子弹到达 → 波次之后判定胜负。死亡即时排除行为，回收不必发生在同一帧。

## 3. 步枪兵索敌与攻击

1. 仅 `Idle` 或 `Aiming` 状态的步枪兵可以攻击。
2. 查询攻击范围内、与士兵之间没有墙体遮挡的存活普通僵尸。
3. 目标按“距离最近”排序；距离相同按 `unit_id` 稳定排序。
4. 目标无效、死亡或离开射程时重新索敌。
5. 到达攻击间隔后创建一条子弹轨迹，轨迹命中后才提交伤害事件。
6. 步枪兵移动状态不索敌、不发射子弹；移动结束后重新开始索敌。

## 4. 子弹轨迹

子弹不是独立战斗单位，不计入单位数量。核心维护飞行位置并检查墙体碰撞，表现层根据事件绘制，不自行决定伤害。

### 发射与命中

- 发射点：步枪兵当前地图坐标。
- 目标点：发射瞬间目标的当前坐标。
- 轨迹：从发射点到目标点的直线插值。
- 飞行速度：`900px/s`。
- 最大飞行时间：`0.35s`。
- 每次更新对前后位置之间的整段轨迹检测墙体，薄墙和大时间步也会停在首次接触点；碰墙产生 `projectile_blocked` 与 `projectile_expired`，不产生目标伤害。
- 正常到达目标点时结算一次；保留最大寿命到期的结算规则。当前 260px 射程小于 315px 最大飞行距离，正常射击会在寿命结束前到达。
- 到达时再次确认目标仍存活，并检查发射点、到达点至目标当前位置的墙体遮挡；目标途中躲到墙后或已死亡时只播放原落点效果，不产生伤害。
- 使用共享 Graphics 绘制浅金色飞行线和亮白弹头，不为每发子弹创建 Node。
- 同一发子弹只产生一次命中事件。

### 轨迹视觉

- 枪口闪光持续 `0.08s`；飞行中显示起点到当前位置的淡线、最长 `44px` 的明亮尾迹和弹头，不提前连接到目标。
- 命中后整段已飞过的轨迹保留 `0.10s` 并淡出，确保同一帧发射并命中的近距离子弹也有可见弹道。
- 命中闪光持续 `0.12s`；墙面接触显示暖色火花，轨迹末端固定在墙面。
- 子弹轨迹不应遮挡单位主体；渲染层低于 HUD、高于单位或作为单位子层。
- 每帧按游戏时间清理过期弹道、枪口与命中效果；终局和重启清空所有临时效果，不影响伤害事件。

## 5. 僵尸移动与近身攻击

1. 僵尸从对应出生区域生成后即直线追击全场最近士兵。
2. `position.y >= defense_line_y` 时标记为 `Breached`，只触发一次破门事件。
3. 每个逻辑步查询全场最近存活士兵，与跨线状态无关。
4. 僵尸与目标距离 `<= 28px` 时停止移动并进入 `Attacking`。
5. 达到累计 `0.13s` 攻击间隔后直接对目标扣除 10 HP。
6. 目标死亡或距离超过范围时重新选择目标并继续移动。
7. 破门不增加僵尸移速，不降低人类防御，不叠加额外伤害。

## 6. 群体移动

- 玩家指令选择点击点固定半径 `112px` 内距离最近、且未死亡的一名士兵。
- 一次指令产生一个 `MoveGroupCommand`，包含单位 ID 列表、目标点和发出时间。
- 每个单位向目标点附近的稳定编队位置移动，避免所有单位重叠在同一点。
- 移动速度使用单位 `move_speed_px_s`；到达距离 `<= 12px` 时视为到达。
- 新指令覆盖旧指令；移动中的单位继续自动索敌和攻击。
- 无法选择到单位时不产生指令，也不改变当前战斗状态。

## 7. 胜负规则

- 所有波次均已生成且存活僵尸数为 0：胜利。
- 存活步枪兵数为 0：失败。
- 同一帧同时满足两者时，优先判定失败，避免玩家全灭后显示胜利。
- 结算触发后停止生成、移动、攻击和伤害，保留结算界面需要的统计快照。

## 9. 首轮调参顺序

1. 先调僵尸生命值和士兵射程，使分批出怪的前几批在挂机时保持可读的接敌节奏。
2. 再调僵尸移速和防线距离，使三波分批进入后仍有足够反应时间。
3. 最后调僵尸近身攻击间隔和伤害，使挂机与微操的胜负差异符合当前关卡目标。
4. 子弹速度只影响观感和响应，不用于弥补战斗数值问题。

## MVP follow-up：当前规则与校准

A/B/C、左中右仅为出生区域和统计标签，不是固定路径。僵尸出生即在全场选择最近存活士兵，每个50ms逻辑步重新决策，同距按稳定ID；无障碍空间内直线追击，遇墙通过墙角可见图绕行。最近目标不可达时选择其他可达士兵，贴墙士兵使用符合僵尸体型的可达接近点；墙边足够三只仍可堆叠翻越，翻墙时不施加单位分离推力。距离<=28px且墙体不阻挡时可近战，防线y=1200只记录首次跨线警告，不是伤害门槛。

当前配置：最多15名士兵，士兵速度48px/s，普通僵尸速度41.9px/s；步枪射程260px、间隔0.35s、单发30点伤害，普通僵尸60HP。士兵与僵尸显示直径分别为28px与32px，出生间距44px。每波按每批5只、间隔1秒从四边进入，三波宣告时间为0/7/20s，整关共350只；波次之间不会清除或重置士兵。50ms固定步上累计攻击时间，单步最多一次。飞行过程按整段轨迹碰墙终止，到达时再确认目标没有躲到墙后。选兵每次只取按下点112px圆内距离最近的一名士兵，向松手点附近的个人落点靠拢。

当前实测：挂机种子1..10均在79.95s胜利，15名士兵存活、0只僵尸；开局单兵微操场景108.85s胜利，14名士兵存活。旧版50人和整波瞬时生成数字不再作为当前基准。

MVP强制3秒自动布阵，无跳过入口；endDeployment仅为内部测试工具。可选微信短振动已实现，同批跨线合并且至少1000ms限频；无能力/抛错/异步失败不阻断战斗，暂停后台不补播、重开重置，物理效果未验证。墙侧阴影与复杂场景经用户确认延期；不扩展其他视觉功能。卡顿策略暂保留，待用户Cocos反馈再决定。Creator导入/真实渲染/构建、手机触控/振动/FPS/内存仍待用户手测，GitHub/许可证/发布暂缓。

当前机器数据见 [验收报告](testing/mvp-test-report.json)，人工检查与填写模板见 [Cocos手测](testing/cocos-manual-checklist.md)。原作OCR保留为历史设计参考，不是本项目测量。
