# 静态二维关卡方案：10个场景初稿 v2

性质：供审核的关卡文案与候选参数，不是已实现关卡，不修改游戏代码。替换此前以对白、救援演出为主的版本；原故事只保留为简短提示背景。

## 项目基线与统一约定

已核对 config/scenes/cabin.json、config/units.json、config/levels.json、src/core/config.ts：项目当前已有矩形墙体与带血量的门配置、南北出生区、小批次生成配置。大屋配置的简介仍写七人，但核心默认已为9人；本稿以核心为参考，不沿用旧50人或旧单位数值。

- 固定单屏、俯视二维、无镜头演出；内部1080×2400，左上原点，x向右、y向下；393×852等手机视口负责显示适配。
- 活动区 x=60..1020、y=180..2160。以下矩形记作[x1,y1,x2,y2]，均为逻辑单位，不是手机像素。
- 候选统一小队：9人，4步枪、2喷火、1盾兵、1狙击、1工程兵；这是比较难度的固定编成草案，不声称当前随机生成一定得到此编成。不上医疗兵、不补兵、不设感染。
- 普通僵尸配置基线：HP60、速度41.9逻辑单位/秒、直径32、单次伤害10、攻击间隔0.13秒；十关统一使用该基线，不用改血量或伤害制造难度。特殊僵尸留到后续单独审核。
- 所有本稿速率均为全地图合计，不是每个入口各一份。每批按激活入口轮流分配，批内沿出生带分散，中心间距至少44；不得从房屋内部或士兵脚下刷出。
- 三段出怪窗口：[0,20)、[20,40)、[40,60)秒，战斗计时不含3秒布阵；每段起点即刷第一批，终点不额外刷本段。60秒后停止生成，继续清理，不把“停止出怪”当胜利。
- 本稿所有建议批次不超过10、间隔不少于0.6秒，与当前配置限制一致；是否需要扩展现有调度表达须实现前另查。
- 统一胜利：计划敌人全部生成完且存活僵尸为0，并至少1名士兵存活。全员死亡失败。不新增护送、搬运、修车、启动设备等交互。
- 静态房屋用矩形墙段与门描述；完整建筑外框不能直接当可进入建筑，必须切分门洞。门宽建议160，墙厚24，门暂用现有600HP作为草案。门被破坏不直接判败。
- 房屋是否挡子弹、屋顶隐藏、不可达目标处理、门破坏及绕行的实际表现，都需结合实现验证；本稿不默认建筑能提供射击掩护。院路保持至少160净宽，不能形成完全封闭出生区。
- 难度D1..D5是出怪量、速率、方向压力的设计预评级，不是已测通关率。同级仍需实测；不声称数值平衡已完成。
- 本稿不是“屏幕外涌入”表现已验证的声明。出生带设在战场边缘；如必须从物理屏幕外进入，要核对逻辑边界、地形入口与裁剪，不能只换负坐标。

## 审核与后续验证

以上建筑、门洞、编成、出怪表均为新建议，不是对现有配置的回写。实施前逐关检查墙段、净宽、出生区不重叠、地图连通、单位半径与队形通行、门破坏与寻路、射击规则；动态移动物体不纳入本稿。

平衡验证需记录：首次接敌时间、首次减员、实际生成数量、峰值在场数、挂机结果、正常指挥结果、卡死/不可达数量。D评级只在同一编成下比较，不能把候选值写成已测通过。

此前10篇剧情中的事件可转成开局/阶段/结算提示文字，作为文案灵感保留；不再以对白、任务NPC、护送和维修作为这批关卡的必要机制。
