# MVP 讨论结论与后续实施 Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保持 MVP 简单可玩的前提下，让僵尸出生后全场自动寻找士兵并追击，加入破门振动，统一范围和手测文档。

**Architecture:** 战斗核心负责目标选择、移动、攻击和破门事件；Cocos/微信适配层负责显示与设备振动。左中右仅保留为出生区域/统计标签，不作为目标过滤或固定行走路径；当前无阻挡障碍，采用直线追击。

**Tech Stack:** TypeScript 无头战斗核心、固定 50ms 逻辑步、Cocos Creator 3.8.8、微信小游戏平台适配。

**Spec:** 本文“讨论结论”为本次需求依据；已有 [问题记录](open-issues-and-decisions.md)、[战斗模型](08-combat-numeric-model.md)、[地图设计](06-map-design.md)、[验收规格](09-mvp-acceptance-and-automation.md) 需在获准实施后同步。

**状态：用户已批准Task1～4；Task1全场追击与Task2限频振动已实现，Task3配对校准/回放及Task4文档与用户手测表已实施，最终自动化结果见 `.superpowers/sdd/mvp-followup/task-3-4-report.md`。** 不提交、不推送、不使用子代理，保留既有工作树。Creator/构建/物理振动和设备验收仍待用户。

## Global Constraints

- MVP 不支持跳过布阵，不新增 UI、快捷键或对外玩法入口；开局仍为强制 3 秒布阵。
- 僵尸出生后直接搜索全场存活士兵，不按 A/B/C 或左中右过滤目标。
- 当前无复杂障碍，自动移动采用直接追击，不宣称已有 A*、导航网格或绕墙能力。
- 僵尸进入近身范围即可攻击；不再以越过防线作为搜索、追击或攻击前置条件。
- 防线仅作空间警戒线；僵尸首次跨过时产生警告与限频振动，不增加攻击、防御或速度系数。
- 首次跨线状态可保留为历史标记；僵尸可以为追击士兵移动回防线上方，不取消追击。
- 保留固定时间波次 0/7/20 秒、50 名初始士兵、350 只普通僵尸、移动中步枪兵停火和同帧失败优先。
- 维持固定步长与不同帧间隔下回放一致性，不以显示帧率驱动不同战斗结果。
- 破门振动属于本次主要反馈；墙面阴影和复杂场景延期，其他非核心视觉项不自动扩展本次范围。
- 卡顿策略保持现状，待用户 Cocos 手测反馈后再决策；不把解释等同用户已批准永久策略。
- 用户后续自行在 Cocos 手动运行测试；微信真机振动、触控、性能等不以模拟测试替代。
- GitHub 发布、许可证、仓库创建和推送暂缓，不在本计划中实施。

## 1. 本次对话结论

| 主题 | 用户确认/当前决定 | 本计划处理 |
|---|---|---|
| 跳过布阵 | 当前 MVP 不支持 | 保留自动 3 秒倒计时；已有内部 endDeployment API 单独标记为非玩家入口，是否保留为测试工具需在实施时明确 |
| 左中右 | 不是规定行走路线 | 文案改成出生区域；ID 不用于限制索敌或追击 |
| 僵尸找兵 | 出生即自动寻找士兵 | 全场最近有效目标，目标死亡/位置改变时重新决策 |
| 近身伤害 | 贴身扣血，无复杂系数 | 无论是否过线，只要达到范围和间隔条件就攻击 |
| 破门反馈 | 加入振动 | 保留警告；振动在适配层实现并限频 |
| 场景表现 | 阴影等复杂内容先不做 | 本期只补闭环必要内容，不扩展复杂地图、障碍或光影 |
| Cocos 测试 | 用户后续手动运行 | 提供操作步骤与记录模板；尚未执行的验证保持待验收 |
| 发布 | 用户稍后处理 | 暂缓许可证、GitHub 与发布操作 |

### 长卡顿说明（解释，不是新需求）

例如一个正常显示帧原本很快完成，但资源加载、GC 或设备负载使画面停顿 300ms，这就是这里讨论的长卡顿。当前 controller 每次最多向战斗推进 50ms，不会在恢复的一帧中补完全部 300ms，代价是游戏时间落后现实时间。核心自身仍以固定步长累计传入时间。此次不改变该策略，也不承诺尚未测得的设备帧率。

## 2. 已有代码与新结论的差异

实施前历史规则为线前只向下、线后找兵，起点配置46px/s、0.25s；Task1已改为从出生全场追击。Task3采用probe3完整配对41.9px/s、0.13s，28px/HP40/伤害10/步枪射程400不变。0.25→0.13s是现有参数平衡校准，不是新机制。当前挂机25.7s首次减员、49.55s失败、57僵尸；24s→y1550、35s→y1750六条A/B/C质心命令74.85s胜利、4人，第二阶段重新采集活兵ID。

旧版实测挂机首次减员 30.30s、失败 47.75s、剩余 69 僵尸；24 秒后撤策略胜利 78.30s、存活 3 人，仅是旧行为的历史证据。新行为必须重新运行，不能复制旧结果或强行保留精确剩余数量。

出生点仍按现有配置生成，不要求本轮删除全部 routeId 字段或破坏波次文件格式；只是改变其语义，不以标签绑定行动。

## Review Focus

1. 防线以上已经贴近士兵的僵尸必须能攻击，不能残留“先过线”条件。
2. 更近目标位于其他出生区域时仍应被选择，目标死亡/士兵移动后必须有效重新索敌。
3. 大批首次破门事件不应造成连续设备振动；暂停、后台、重开及不支持设备不能重播历史反馈或影响战斗。
4. 追击修订可能改变胜负与卡顿负载，需比较完整单位/事件而非只看一个通关截图。
5. 所有文档必须区分直接追击、复杂绕障寻路和待用户手测，不将计划项标成已完成。
