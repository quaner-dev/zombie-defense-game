# 当前问题与讨论决策记录

## 口径与使用方式

本轮已采用41.9px/s、0.13s配对校准和六命令，挂机33.55s/68.65s/17，指挥68.05s/22人。完整自动化证据与计数以本轮报告为准，不再沿用屏幕外出生配置前的历史口径；Creator/微信/真机仍未验收，真机按后续计划执行。

每项区分问题性质、影响、建议、关闭条件与决策状态。建议不是已经批准的变更；讨论后在末尾追加决定，再执行对应工作。本文不修改代码、授权、发布范围或验收门槛。

## A. 已知代码边界与测试缺口

### TOOL-HISTORY-01：内部endDeployment布阵余量（非MVP玩家缺陷）

- 性质：已复现的轻微时钟边界。
- 现象：`advance(0.019)` → `endDeployment()` → `advance(0.031)` 会发布 0.05 秒战斗步；前 19ms 原属于布阵。
- 影响：手动跳过布阵接口最多引入不足 50ms 的边界偏移；正常自动倒计时流程不调用该接口。
- 建议：显式结束布阵时丢弃布阵余量，并明确新阶段从零累计时间。
- 关闭条件：增加跳过布阵/零时长/重复调用测试，自动布阵与回放等价测试仍通过。
- 状态：MVP明确不支持跳过布阵；仅保留内部测试工具历史边界，不是本期玩家功能待修项。

### CFG-01：出生布局配置缺少严格校验

- 性质：配置健壮性缺口。
- 影响：非法列数或间距可能生成 NaN 坐标；目前随仓配置有效，不代表用户新增地图也安全。
- 建议：加载时拒绝缺失、非有限、非正整数列数和负间距，给出字段及路线错误；保留未设置布局时的明确默认值。
- 关闭条件：非法配置用例被拒绝；正常布局、边界限制和现有关卡测试通过。
- 状态：待确认校验策略。

### TEST-01：报告 CLI 未主动测试失败退出路径

- 性质：测试覆盖不足，不是已证实的退出码错误。
- 建议：用可控失败场景验证写出真实失败报告且退出码为 1；正常场景退出码为 0。
- 关闭条件：两个方向均由真实子进程测试覆盖，不依赖当前关卡偶然失败。
- 状态：待补测试。

### TEST-02：20 局节点稳定性检查未覆盖完整后代树

- 性质：测试覆盖不足，未确认实际泄漏。
- 影响：根节点 children 数不变仍可能掩盖 Battlefield 下的节点增长。
- 建议：递归统计后代节点、相关组件及池中活动对象；真机另测 JS/native/GPU 内存。
- 关闭条件：递归生命周期回归通过；真机内存项单独记录，不能以替身测试替代。
- 状态：待补测试。

## B. 工具、行为与视觉差异

### TOOL-01：场景 author 工具依赖历史样本输入

- 性质：辅助工具可复现性不足；不等于正常 sync/import 流程失效。
- 建议：提供可再分发的明确样本来源与获取方式，或者将该工具标为历史实验并移出推荐入口。
- 关闭条件：公开源码环境可按说明运行，或明确不作为支持工具。
- 状态：待确定保留方式，涉及第三方材料授权。

### VIS-01：视觉实现与引擎预览仍需确认

- 当前要求已写入适配层：按钮按下高亮、选中淡入、较小移动箭头、移动目标点、破门闪烁/抖动、近战受击脉冲和子弹命中亮点脉冲；自动测试覆盖了这些状态。
- 弯曲手势预览/取消淡出、墙侧阴影和复杂场景不是本轮要求；破门短振动已实现但物理效果仍未验证。
- 关闭条件：Creator 预览确认中文 HUD、Graphics 尺寸和动效节奏，或记录具体渲染问题。
- 状态：代码实现，等待 Creator 运行证据；延期项已明确，不再作为本轮缺陷。

### BEH-01：长卡顿下的时间推进策略

- 性质：明确的当前策略，不是已证实缺陷。
- 现状：核心固定 50ms 步进、保留累计余量；controller 每帧最多推进 50ms，长卡顿会使游戏时间落后墙钟。
- 建议：MVP 可先保留以限制追帧压力；真机后再决定采用有上限追帧还是持续慢速。
- 关闭条件：策略写明，并用长卡顿/后台恢复场景验证；若改动，不破坏同输入回放一致性。
- 状态：待明确接受或调整。

### BEH-02：路线归属与性能扩展边界

- 现状：routeId 保持出生归属；跨路移动直线进行，墙不阻挡；事件保留本局完整历史；每帧单位副本、Graphics 重建、逐攻击者索敌有待分析。
- 影响：后续按“当前所在路线”统计或加入复杂地图/无限模式时，不能直接沿用现有假设。
- 建议：本期保持文档披露，不先扩展寻路或无限模式；依据 profiler 决定优化。
- 关闭条件：MVP 范围被确认，后续新增需求建立独立设计。
- 状态：本期明确A/B/C是出生区域，不限制僵尸全场最近索敌；从出生即直线追击。复杂障碍寻路延期，其他性能限制保留。

## C. 发布验证缺口

### ENV-01：Creator 与平台构建未实际验收

- 未完成：Creator 3.8.8 导入/保存/预览、Web Mobile 构建运行、微信小游戏构建和开发者工具预览。
- 影响：不能保证实际引擎中无导入、渲染或平台问题，也没有已验收的微信包。
- 建议：先 Creator + Web Mobile，再微信导出与真机；使用说明见根目录 README-cocos。
- 关闭条件：留存工具版本、构建日志、画面及操作验收结果；新缺陷另登记。
- 状态：待具备环境与合法授权信息后执行。

### PERF-01：设备性能与手感未实测

- 未完成：目标机型 FPS、>200ms 卡顿、触控反馈、真实内存/GC、峰值弹道、安全区、长时间运行。
- 现有统计不是 GPU 耗时或物理 touch-to-photon；自动化对象清理测试不是内存稳定证明。
- 建议：先列实际可用安卓/iPhone 设备；按发布清单采样，不凭模拟器声明 60FPS 达标。
- 关闭条件：命名设备与环境下记录指标，明确通过/未通过及降级方案。
- 状态：待设备矩阵与实测。

### ENV-02：Node / 操作系统支持与 CI 未确定

- 已执行环境：Linux、Node v26.7.0；不能据此承诺 Node 20/22 或 Windows 支持。
- 建议：明确首版支持矩阵，实际测试后增加 engines/CI；CI 不能替代 Creator 与真机验证。
- 关闭条件：支持版本有真实结果，干净检出安装/生成/测试可复现，CI 工作流实际执行通过。
- 状态：待确定支持范围。

## D. GitHub 公开前决策

### OSS-01：许可证与第三方权利

- 项目许可证未选择，尚无 LICENSE；不能声称已获得开源再分发授权。
- 需要检查：玩法灵感来源、名称和素材、Cocos 场景参考、依赖许可与署名条件。注明出处不等于取得授权。
- 建议：先确定是否倾向宽松使用、是否需要明确专利条款，再选 MIT / Apache-2.0 等；许可证选择无法解决第三方素材权利。
- 关闭条件：所有者确认许可证，加入匹配文本和必要 notices，第三方来源完成核查。
- 状态：待用户决策；不代为选择。

- 大量开发修改尚未提交，不能把当前 Git HEAD 当作完整交付；历史材料仍可能有私人路径和内部报告。
- 建议：审核整个发布树与历史，保留公开所需文档、剔除内部执行记录/凭据；确认仓库名称、发布阶段及安全反馈渠道，再整理提交。
- 关闭条件：完整树/历史审查、文件清单、许可证和发布说明就绪；提交与推送得到授权并读回验证。

## 建议讨论顺序

1. 定义首个 GitHub 版本是“开发预览源码”还是“完成微信真机验收的 MVP”。这决定发布前哪些环境证据必须具备；都必须如实标注状态。
2. 确认 BUG-01 / CFG-01 / TEST-01 / TEST-02 是否本轮处理。建议优先补齐，范围小且利于公开维护。
3. 确定视觉首版要求与长卡顿策略。
4. 确定许可证、运行环境矩阵和实际可用 Creator/微信/设备测试环境。
5. 完成隐私与第三方审查后，再决定提交、创建仓库和发布。
