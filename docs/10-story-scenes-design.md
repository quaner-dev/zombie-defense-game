# 故事与场景设计稿

本次方案把“场景内容”和战斗规则分开。玩家进入游戏先选择故事模式或场景演练；故事模式从大屋开始，完成大屋三波后进入大楼楼下。每个场景只安排三波，第三波全部生成并清场、至少一名人类存活才算通关。

配套的 [可交互设计预览](design/scenes-preview.html) 可直接用浏览器打开，查看入口、场景卡片、大屋与大楼楼下的俯视布局。预览是流程与空间设计稿，战斗仍在 Cocos 的 `Battle.scene` 中运行。

## 1. 入口与章节流程

```mermaid
flowchart TD
  A[进入游戏：选择模式] --> B[故事模式]
  A --> C[场景演练]
  B --> D[第一幕：大屋守卫 / 3 波]
  D -->|胜利，点击进入大楼楼下| E[第二幕：楼下集结 / 3 波]
  D -->|失败| F[重开当前场景]
  E -->|失败| F
  F --> G[重新进行当前场景的 3 秒布阵]
  E -->|胜利| H[故事通关]
  C --> I[选择大屋或大楼楼下]
  I --> J[独立挑战 / 3 波]
  J --> K[重开 / 返回首页]
```

- **故事模式**：强调从室内突围到室外街区的连续体验。第一关结算保留用时和存活人数，显示“进入大楼楼下”；点击后开始第二关的 3 秒布阵。第二关胜利显示“故事通关”。
- **场景演练**：显示地图缩略图、地点、场景名、三波目标，两个场景均可直接选择；演练胜利后不触发故事跳关。
- **战斗页面**：显示模式、当前场景、人类/僵尸数量、`第 n/3 波`、用时，以及暂停、重新开始、返回首页。失败时只能重试或返回，不能进入下一关。
- **本版衔接规则**：每关重新生成 7 人小队（4 名步枪兵、2 名喷火兵、1 名盾兵）。重开仍是当前关，大门耐久恢复。过关、选关和重开时清空旧子弹、选中单位、指令预览、波次动画和事件游标。
- **进度规则**：本版为一次会话内的顺序推进；返回首页后重新选择故事，从第一关开始。解锁、跨次存档、伤兵继承和成长系统留给后续单独设计。

两张地图都明确配置为三波，每波按每批 10 只、间隔 0.5 秒生成；相较上一版每批 5 只、间隔 1 秒，单波入场速率从每秒 5 只提高到 20 只。大屋和楼下的总数分别从 350/135 加倍到 700/270 只。波次重叠时各自继续出怪。

## 2. 场景一：大屋守卫（已接入）

**地点与情绪**：临时落脚的大屋内部。七人小队初始部署在大厅中央；僵尸从南北入口进入，先攻击入口大门，破门再进入。喷火兵适合在入口持续覆盖密集尸群。

**视觉**：深灰地面、开阔的大屋大厅、灰色外围墙体、暖棕色门扇与独立耐久条。喷火显示红橙色外焰、亮黄焰心和摆动扩散。背景与装饰不参与碰撞；完整墙体阻挡移动和射击，门只阻挡移动。

**地形**（地图原点在左上，尺寸 1080×2400，以下均为地图像素）：

| 区域/构件 | 坐标范围 | 作用 |
|---|---|---|
| 大屋大厅 | x=124–956，y=704–2040 | 七人队伍部署区，室内保持连通 |
| 西侧外围墙 | x=100–124，y=680–2064 | 阻挡移动、视线和子弹 |
| 东侧外围墙 | x=956–980，y=680–2064 | 阻挡移动、视线和子弹 |
| 北侧入口 | x=477–603，y=680–704 | 600 HP 大门，僵尸从北侧逼近 |
| 南侧入口 | x=477–603，y=2040–2064 | 600 HP 大门，僵尸从南侧逼近 |

僵尸规划经过门口的路径，在门前停下攻击；耐久归零后门停止阻挡，寻路缓存随之刷新。完整墙体仍然阻挡，不能把攻击目标直接投射到墙后。守军可以隔门攻击门外目标，喷火持续覆盖入口。

## 3. 场景二：楼下集结（已接入）

**地点与情绪**：离开大屋后抵达大楼楼下的开放区域。四块建筑基座夹出纵向街道和横向广场，空间由室内大厅变为建筑之间的街角。

**视觉**：蓝灰色路面、略亮的十字通道、混凝土建筑矩形、中央断续道路标线。建筑以矩形轮廓表达，避免圆形或接近正方形的障碍物。装饰标线没有碰撞。

**布局**：

```text
                     北侧来敌
        ┌─────────┐           ┌─────────┐
        │ 西北大楼 │ 纵向街道  │ 东北大楼 │
        │ 240×620 │  宽280    │ 240×620 │
        └─────────┘           └─────────┘
 西侧来敌 ←       集结广场 / 横向通道        → 东侧来敌
        ┌─────────┐           ┌─────────┐
        │ 西南大楼 │  后撤路   │ 东南大楼 │
        │ 240×480 │           │ 240×480 │
        └─────────┘           └─────────┘
                     南侧来敌
```

| 建筑墙体 | 左上角 | 宽 × 长 | 作用 |
|---|---|---|---|
| 西北大楼 | (160, 460) | 240 × 620 | 提供西北街角遮挡 |
| 东北大楼 | (680, 460) | 240 × 620 | 对称形成 280 像素的中央通道 |
| 西南大楼 | (160, 1480) | 240 × 480 | 比大屋外围墙更宽、更长，留出南侧回转空间 |
| 东南大楼 | (680, 1480) | 240 × 480 | 提供东南方向的转角与遮挡 |

横向通道位于 y=1080–1480，净宽 400；纵向通道位于 x=400–680，净宽 280；两侧外围各保留 100 像素步行带。七人小队初始集结在 (540,1280) 附近。所有初始单位和四边出生点都在墙外。

**玩法重点**：

- 宽墙使射击视线中断得更明显。守在街角可缩小同时接敌的范围，但向墙后移动也可能让士兵暂时失去火力覆盖。
- 敌人从南北进入时，中央街道形成长轴压力；东西夹击迫使玩家选择向南/北撤离，而不能一直停留在十字中心。
- 建筑阻挡移动与射击，僵尸沿可见拐角绕行。当前场景没有配置翻墙；只有显式配置 `stackRequired` 的独立路障支持堆叠翻越。拥挤位移也检查整段碰撞，避免被挤过薄墙或卡入墙内。

**三波节奏**（新增关卡的初始调参值）：

| 波次 | 战斗时间 | 数量与方向 | 体验目标 |
|---|---|---|---|
| 1 | 0 秒 | 60 只，北/南/东/西各 15 | 认识四面来敌与建筑遮挡 |
| 2 | 14 秒 | 90 只，北 24，南/东/西各 22 | 四侧包夹，调整街角站位 |
| 3 | 30 秒 | 120 只，四侧各 30 | 四向压力下沿街转移并清场 |

总计 270 只，每波都有四侧来敌。第二关以宽墙和射线遮挡形成变化，当前数量是可调的起点，不能当成已经通过人工试玩的难度结论。

**通关文案**：“楼下区域已清理，队伍暂时安全。”当前故事在第二幕结束，提供重开和返回首页。

| 撤离广场 | 开阔地面、长方形公交站与围栏、北侧撤离平台 | 少量散兵从外围逼近 | 主要压力转移到撤离方向 | 四边最后合围 | 在“守住火力点”和“保持撤离通道”之间分配队伍 |

## 5. 场景扩展方式

新增场景前，必须先按 [开发指南的确认清单](development.md#新增场景前的确认) 向用户确认生成速度、出生位置与比例、士兵编制与站位、布阵时间和场景目标，并记录到该场景的设计文档；未确认的关键项不能自行沿用旧地图默认值。

场景模块在 `src/scenes/`，统一实现 `SceneDefinition`：

- `id / title / subtitle / briefing / objective`：入口、卡片、HUD 与结算文案。
- `mapId / map`：设计尺寸、战斗边界、选兵半径、初始部署点、出生点、矩形地形。
- `levelId / level`：场景自己的波次或连续生成配置、敌人类型、来源、数量、分批大小与间隔；连续模式读取 `continuousSpawn`，出生位置读取 `map.spawnPoints`。
- `presentation`：地面、墙体、轮廓颜色与无碰撞装饰。

第一关集中于 `config/scenes/cabin.json`，由 `src/scenes/cabin.ts` 导出。兼容关卡配置 `config/levels.json` 同步保留第一关波次；`config/map.json` 用于基础地图回归。第二关集中于 `config/scenes/courtyard.json`，由 `src/scenes/courtyard.ts` 导出；第三关为 `config/scenes/villa-rescue.json`。楼下和别墅现已使用各自的连续生成配置，本稿前文的楼下三波描述保留为历史设计。新增后续场景时：

1. 完成前置确认后，在 `config/scenes/` 新建场景 JSON，按确认结果定义波次或连续生成、地图和文案。
2. 在 `src/scenes/` 增加对应模块，并加入 `index.ts` 的 `SCENES` 列表；顺序即故事推进顺序。
3. 地图加载、波次加载、场景卡片、下一关判断都从列表派生；地图绘制与输入从当前战斗的 `MapModel` 读取。
4. 执行 `npm run sync:core`、本次场景回归、两项类型检查和 bundle 检查。生成目录不手工修改。

只有一份 Cocos `Battle.scene`，它作为通用战斗容器；增加一个地点不需要复制整套控制器或另造一套战斗系统。现有的 `MapModel.register`、`WaveManager.register` 接口继续可用。

## 6. 验证与试玩要点

自动回归重点：菜单冻结时钟与战场输入、真实按钮进入故事/演练、三波配置有效、胜利前不能跳关、故事的下一关与末关结算、演练不自动推进、重开当前场景、切换时清空旧显示，以及宽墙的移动/射线阻挡和可绕行路径。

当前验证与历史记录见 [场景扩展验证记录](testing/scenes-test-report.md)。

Creator 试玩重点：入口与场景卡片的中文换行、不同屏幕下点击区域、门耐久与破门反馈、喷火覆盖与墙体遮挡、建筑周边绕行、密集尸群不卡墙，以及七人抵御加倍尸潮的实际难度。自动测试和静态预览不替代这些引擎内观察。
