# MVP 验收与自动化测试规格（v1.0）

> 关卡：`LV01_zombie_wave`
> 目的：把设计目标转换为可重复运行、可定位失败原因的验收项目。
> 本文只覆盖 MVP：固定时间出怪、三路、普通僵尸、群体移动、子弹轨迹和简化破门。

## 1. 测试原则

- 战斗模拟支持固定随机种子；MVP 默认不使用影响战斗结果的随机数。
- 测试同时记录游戏时间和真实运行时间。
- 单元测试验证规则；模拟测试验证整局节奏；真机测试验证触控和性能。
- 任何失败必须指出阶段：波次、移动、索敌、子弹、伤害、破门或结算。

## 2. 自动化测试接口

测试环境至少提供以下能力：

```ts
interface BattleTestHarness {
  start(levelId: string, seed: number): void; // start enters the 3s deployment phase
  advance(seconds: number): void;
  issueMoveAt(x: number, y: number, targetX: number, targetY: number): void;
  getSnapshot(): {
    time_s: number;
    aliveHumans: number;
    aliveZombies: number;
    spawnedZombies: number;
    waveIndex: number;
    breachedRoutes: string[];
    result: "running" | "win" | "lose";
  };
  getEvents(): Array<{ type: string; time_s: number; data: unknown }>;
}
```

自动化测试不依赖渲染截图判断战斗结果；截图只用于视觉回归。

## 3. 波次测试

| 用例 | 操作 | 通过标准 |
|---|---|---|
| W1 | 结束 3 秒布阵并推进战斗计时到 `0.1s` | 生成 50 只，全部 route=`B` |
| W2 | 布阵结束后推进战斗计时到 `6.99s` | 第 2 波尚未生成 |
| W3 | 推进战斗计时到 `7.0s` | 新增左路 50、右路 50，总生成 150 |
| W4 | 推进战斗计时到 `19.99s` | 第 3 波尚未生成 |
| W5 | 推进战斗计时到 `20.0s` | 新增左路 60、中路 80、右路 60，总生成 350 |
| W6 | 让前波存活后推进战斗计时 | 第 2、3 波仍按 7s、20s 触发，不等待清波 |
| W7 | 推进到 `20.1s` 后统计类型 | 350 只全部为 `normal_zombie` |

允许时间误差：模拟器 `±0.05s`；显示层横幅允许 `±0.1s`。

## 4. 移动测试

- M1：点击 17 个兵所在区域并拖到左路防守点，必须生成一个群体移动指令，不得只移动 1 个单位。
- M2：同一区域连续发出新指令，新目标必须覆盖旧目标。
- M3：移动期间推进 1 秒，步枪兵不得产生新的攻击伤害事件。
- M4：到达目标点误差 `<=12px` 后，步枪兵恢复索敌和攻击。
- M5：点击空白且半径 72px 内无存活步枪兵，不产生移动指令。
- M6：目标点超出边界时，所有单位最终位置必须落在地图边界内。

## 5. 战斗与子弹测试

- C1：静止步枪兵在 400px 内有僵尸时，按 0.5 秒攻击间隔发射。
- C2：每次发射创建一条从发射点到目标点的子弹轨迹，轨迹对象有开始和结束事件。
- C3：子弹飞行期间目标死亡，子弹完成表现但不产生伤害。
- C4：同一子弹只产生一次伤害事件。
- C5：普通僵尸 HP=40，受到 4 次 10 点有效伤害后死亡一次。
- C6：僵尸未越过 `y=1200` 时不得产生近身伤害。
- C7：僵尸与步枪兵距离 `<=28px` 时，无论是否过线，按累计 0.13 秒间隔造成一次 10 点伤害（每次更新最多一次）。
- C8：移动中的步枪兵没有攻击目标、子弹和伤害事件。

## 6. 破门与结算测试

- B1：任意僵尸首次达到 `y>=1200` 时产生一次 `route_breached` 事件。
- B2：同一僵尸继续在防线以下移动，不重复产生破门事件。
- B3：所有人类 HP 归零后，结果为 `lose`，并停止后续伤害和刷新。
- B4：所有波次已生成且僵尸归零后，结果为 `win`。
- B5：同一帧人类和僵尸同时归零，结果为 `lose`。
- B6：结果确定后，重复调用 `advance()` 不改变统计快照。

## 7. 挂机节奏测试

挂机定义：启动后不发送任何移动指令，连续运行 10 次；每次使用种子 `1..10`。如果战斗无随机性，10 次结果必须一致。

首轮目标范围：

| 指标 | 目标 |
|---|---:|
| 第 1、2 波人类损失 | 0，允许最多 2 人 |
| 首次减员时间 | 25~35s |
| 人类全灭时间 | 38~50s |
| 结算时剩余僵尸 | 全场追击校准实测并锁定确定性回归值57 |

如果挂机直接胜利，说明火力或防线压力不足；如果第 1、2 波就大量减员，说明出生位置、射程或移动速度需要先校准。

## 8. 指挥通关测试

提供可重复的本路后撤脚本，不依赖人工反应时间：

1. `start()` 后 `advance(3)` 结束布阵，战斗钟从 0 开始。
2. 战斗 `24s`，按 A/B/C 顺序，在每路存活步枪兵的实际质心点击，以正常 72px 规则选中该路兵群。
3. 24s发送A/B/C三条指令到 `(180,1550)`、`(540,1550)`、`(900,1550)`；35s重新采集当前活兵质心与ID，再发A/B/C三条到各自x、y1750，共六条。
4. 报告记录两阶段实际事件时间、issuedAt、当前质心、预期ID和选中ID，逐一比较；两个阶段均17/17/16人。

通过标准保持：结果必须为 `win`，人类存活数大于 0，120s 内结束。无损通关仍为高目标。

**历史与当前裁决**：四命令增援及旧24s单阶段后撤保留为历史诊断，旧78.30s/3人不再是当前结果。全场追击采用probe3验证的24s/35s两阶段共六命令，74.85s胜利、4人；硬目标未放宽，`scripts/reinforcement.mjs`仍仅为可选诊断。

## 9. 性能测试

峰值场景：50 名步枪兵、350 只僵尸分批存在、64 条子弹表现对象、连续移动指令和 HUD 更新。

- 中高端设备平均 `60 FPS`。
- 低端目标设备平均不低于 `50 FPS`。
- 不出现超过 `200ms` 的卡顿尖峰。
- 移动指令到第一帧反馈不超过 `100ms`。
- 单局开始和结束后对象池数量回到基线，连续重开 20 局无持续内存增长。

## 10. 测试报告格式

每次自动化运行保存以下字段（下方为格式示例，不是实测结果；实际 JSON 另含 policy、config、game_time_s、real_runtime_ms、损失、射击诊断及命令证据）：

```json
{
  "level_id": "LV01_zombie_wave",
  "seed": 1,
  "result": "lose",
  "first_casualty_time_s": 29.4,
  "human_alive_at_end": 0,
  "zombie_alive_at_end": 91,
  "wave_spawn_times_s": [0.0, 7.0, 20.0],
  "breached_routes": ["B", "A", "C"],
  "assertions_failed": []
}
```

报告用于比较每次调参前后的结果，不把单次试玩感觉当作数值结论。

## MVP follow-up：当前规则与校准

A/B/C、左中右仅为出生区域和统计标签，不是固定路径。僵尸出生即在全场选择最近存活士兵，每个 50ms 逻辑步重新决策，同距按稳定 ID；无障碍空间内直线追击，未实现 A*、导航网格或绕墙。距离 <=28px 即可近战，防线 y=1200 只记录首次跨线警告，不是伤害门槛，也不改变速度、伤害或防御；追击可返回线上方。

当前配置采用 probe3 的完整配对：僵尸速度 **41.9px/s**、攻击间隔 **0.13s**。间隔从 0.25→0.13s 是现有参数的平衡校准，不是新增机制；50ms 固定步上累计攻击时间，单步最多一次。HP40、单次伤害10、步枪HP100/伤害10/射程400/间隔0.5s/速度120、弹速900/寿命0.35s 均未改；九列5px出生布局、50人、350僵尸和0/7/20s波次保留。

当前实测：挂机种子1..10首次减员 **25.7s**，**49.55s失败，0人/57僵尸**；指挥 **53.85s** 首次减员，**74.85s胜利，4人/0僵尸**。使用六条正常群体命令：战斗24s按A/B/C当前活兵质心选择，分别到(180,1550)/(540,1550)/(900,1550)；35s重新捕获当前活兵质心与ID，再分别到(180,1750)/(540,1750)/(900,1750)。两阶段实际选择17/17/16人；没有隐藏加伤、增兵或特殊胜利。旧30.30s/47.75s/69与78.30s/3仅为线后追击历史，当前报告已替换，不再作为当前精确预言。25..35s首次减员、38..50s挂机失败、指挥胜利且存活>0及完整快照/单位/事件分段等价仍是硬目标。

MVP强制3秒自动布阵，无跳过入口；endDeployment仅为内部测试工具。可选微信短振动已实现，同批跨线合并且至少1000ms限频；无能力/抛错/异步失败不阻断战斗，暂停后台不补播、重开重置，物理效果未验证。墙侧阴影与复杂场景经用户确认延期；不扩展其他视觉功能。卡顿策略暂保留，待用户Cocos反馈再决定。Creator导入/真实渲染/构建、手机触控/振动/FPS/内存仍待用户手测，GitHub/许可证/发布暂缓。
