# MVP 验收与自动化测试规格（当前配置）

> 场景：`LV01_zombie_wave`（小屋）、`LV02_courtyard_wave`（楼下）
> 目的：把设计目标转换为可重复运行、可定位失败原因的验收项目。
> 当前队伍为 7 人（4 步枪兵、2 喷火兵、1 盾兵）；大屋有 2 扇可破坏门，楼下从四边出怪。

## 1. 测试原则

- 战斗模拟支持固定随机种子；MVP 默认不使用影响战斗结果的随机数。
- 测试同时记录游戏时间和真实运行时间。
- 单元测试验证规则；模拟测试验证整局节奏；真机测试验证触控和性能。
- 任何失败必须指出阶段：波次、移动、索敌、子弹、伤害、破门或结算。

## 2. 自动化测试接口

测试环境至少提供以下能力：

```ts
interface BattleTestHarness {
  start(levelId: string, seed: number): void; // start enters the 3s deployment phase
  advance(seconds: number): void;
  issueMoveAt(x: number, y: number, targetX: number, targetY: number): void;
  getSnapshot(): {
    time_s: number;
    aliveHumans: number;
    aliveZombies: number;
    spawnedZombies: number;
    waveIndex: number;
    breachedRoutes: string[];
    result: "running" | "win" | "lose";
  };
  getEvents(): Array<{ type: string; time_s: number; data: unknown }>;
}
```

自动化测试不依赖渲染截图判断战斗结果；截图只用于视觉回归。

## 3. 波次测试

| 用例 | 操作 | 通过标准 |
|---|---|---|
| W1 | 小屋结束 3 秒布阵 | `0s` 触发 100 只的波次声明；首批生成 10 只，出生点仅为北侧入口和南侧入口 |
| W2 | 小屋推进到 `6.99s`、再到 `7s` | 第二波只在 `7s` 触发；配置 200 只，单批最多 10 只、批间隔 0.5s |
| W3 | 小屋推进到 `19.99s`、再到 `20s` | 第三波只在 `20s` 触发；配置 400 只，三波累计配置 700 只 |
| W4 | 等待小屋全部批次完成 | 僵尸从南北入口生成；每批最多 10 只、间隔 0.5s，波次不等待清场 |
| W5 | 楼下推进到 `0/14/30s` | 三波配置分别为 60/90/120 只，总计 270 只；出生点仅为北、南、东、西 |
| W6 | 比较两种场景的批次事件 | 每个场景使用自身 wave config；出怪计数不得在波次声明时误判为已经全部入场 |

允许时间误差：模拟器 `±0.05s`；显示层横幅允许 `±0.1s`。

## 4. 移动测试

- M1：点击一个存活士兵并拖到左路防守点，必须生成只包含该士兵 ID 的移动指令。
- M2：同一区域连续发出新指令，新目标必须覆盖旧目标。
- M3：移动期间推进 1 秒，若射程内有僵尸，移动中的士兵仍应产生射击事件。
- M4：到达目标点误差 `<=12px` 后，士兵清除移动目标并继续自动索敌和攻击。
- M5：点击空白且半径 112px 内无存活士兵，不产生移动指令。
- M6：目标点超出边界时，被控制士兵最终位置必须落在地图边界内。

## 5. 战斗与子弹测试

- C1：静止士兵在各自配置射程内有僵尸时，按其攻击间隔发射。
- C2：每次发射创建一条从发射点到目标点的子弹轨迹，轨迹对象有开始和结束事件。
- C3：单体子弹飞行期间目标死亡，子弹完成表现但不产生伤害；喷火仍对喷射范围内其他存活僵尸结算。
- C4：同一单体子弹只产生一次伤害事件；同一发火焰可以对多个目标各结算一次。
- C5：普通僵尸 HP=60，受到两次 30 点步枪伤害后死亡一次。
- C6：僵尸第一次跨过 `y=1200` 时仅产生一次警告；防线两侧的近战资格相同。
- C7：僵尸进入自身攻击范围且路径无遮挡后，按其配置间隔造成配置伤害（每次更新最多一次）。
- C8：移动中的人类士兵仍可在射程内索敌并产生射击事件，移动状态不会被射击打断。
- C9：喷火兵对朝目标逐渐加宽的喷射通道内多个僵尸结算伤害，末端半径 `72px`；墙体遮挡伤害，房门允许守军射击。表现层绘制红橙外焰、亮色焰心和火团。

## 6. 破门与结算测试

- B1：小屋挡住目标路线的门初始为 600 HP；普通墙不会被僵尸近战破坏。
- B2：僵尸抵达挡路的门后攻击门；门耐久降到 0 后可通过门洞，再攻击大厅内目标。
- B3：重开或切换场景后，已损坏的门恢复初始耐久。
- B4：任意僵尸首次达到 `y>=1200` 时产生一次 `route_breached` 警告事件。
- B5：所有人类 HP 归零后，结果为 `lose`，并停止后续伤害和刷新。
- B6：所有波次已生成且僵尸归零后，结果为 `win`。
- B7：同一帧人类和僵尸同时归零，结果为 `lose`。
- B8：结果确定后，重复调用 `advance()` 不改变统计快照。

## 7. 挂机节奏测试

挂机定义：启动后不发送任何移动指令，连续运行 10 次；每次使用种子 `1..10`。如果战斗无随机性，10 次结果必须一致。

首轮目标范围：

| 指标 | 目标 |
|---|---:|
| 人类损失 | 以最新配置生成的报告记录，不沿用旧人数结果 |
| 结算时间 | 以最新配置生成的报告记录 |
| 结算结果 | 必须结束为胜利或失败；胜利时 7 人编成的剩余人数和僵尸数必须与事件一致 |

以上为当前本地自动化测量；配置或关卡变化后以重新生成的验收报告为准。

## 8. 指挥通关测试

提供可回放的大厅内单兵调整脚本，不依赖人工反应时间：

1. `start()` 后 `advance(3)` 结束布阵，战斗钟从 0 开始。
2. 从七人队伍读取实际位置，在指定存活士兵位置按下；每次按下按 `112px` 规则只捕获距离最近的一名士兵。
3. 将士兵移到大屋大厅内的可达点；具体目标与单位 ID 由 `scripts/run-acceptance.mjs` 记录。每条事件只能包含一个存活人类 ID，不再用旧 A/B/C 三队坐标。
4. 报告记录每条事件的时间、issuedAt、按下点和实际选中 ID，逐一比较；空白拖动不得产生指令。

通过标准保持：结果必须为 `win`，人类存活数大于 0，120s 内结束。无损通关仍为高目标。

**历史与当前裁决**：旧的群体调度脚本与出生点数据保留为历史诊断；当前验收以单兵微操和移动中持续射击为准。

## 9. 性能测试

峰值场景：7 名混合士兵、700 只分批生成的僵尸、最多 64 条并行子弹表现对象、连续移动指令和 HUD 更新。

- 中高端设备平均 `60 FPS`。
- 低端目标设备平均不低于 `50 FPS`。
- 不出现超过 `200ms` 的卡顿尖峰。
- 移动指令到第一帧反馈不超过 `100ms`。
- 单局开始和结束后对象池数量回到基线，连续重开 20 局无持续内存增长。

## 10. 测试报告格式

每次自动化运行保存以下字段（下方为格式示例，不是实测结果；实际 JSON 另含 policy、config、game_time_s、real_runtime_ms、损失、射击诊断及命令证据）：

```json
{
  "level_id": "LV01_zombie_wave",
  "seed": 1,
  "result": "lose",
  "first_casualty_time_s": 29.4,
  "human_alive_at_end": 0,
  "zombie_alive_at_end": 91,
  "wave_spawn_times_s": [0.0, 7.0, 20.0],
  "breached_routes": ["B", "A", "C"],
  "assertions_failed": []
}
```

报告用于比较每次调参前后的结果，不把单次试玩感觉当作数值结论。

## MVP follow-up：当前规则与校准

A/B/C 是统计标签，不是固定路径。僵尸每个 50ms 逻辑步重新选择最近的可达存活士兵，按墙角可见图绕墙；大屋路线被门挡住时先攻击门，门毁后进入大厅。距离不超过 28px 且没有墙体遮挡时可近战。`y=1200` 只记录首次跨线警告，不限制追击方向或伤害。

当前大屋 7 人守军对抗 700 只僵尸；从北、南入口生成，波次为 0/7/20s、每波 100/200/400 只。楼下为四边生成，波次为 0/14/30s、每波 60/90/120 只。两场景均每批 10 只、间隔 0.5s。士兵可在移动中继续攻击，战斗采用 50ms 固定步进。

当前挂机与微操结果见 [本轮验证记录](testing/scenes-test-report.md)，可用 `npm run acceptance:report -- --output dist/reports/mvp-test-report.json` 重生完整 JSON。已保存的 [旧验收报告](testing/mvp-test-report.json) 以及此前 15 人与 350 只大屋波次的 79.95s 等结果来自旧配置，只作为历史记录，不作为本版通过标准。

MVP强制3秒自动布阵，无跳过入口；endDeployment仅为内部测试工具。可选微信短振动已实现，同批跨线合并且至少1000ms限频；无能力/抛错/异步失败不阻断战斗，暂停后台不补播、重开重置，物理效果未验证。墙侧阴影与复杂场景经用户确认延期；不扩展其他视觉功能。卡顿策略暂保留，待用户Cocos反馈再决定。Creator导入/真实渲染/构建、手机触控/振动/FPS/内存仍待用户手测，GitHub/许可证/发布暂缓。

当前机器数据见 [本轮验证记录](testing/scenes-test-report.md)，人工检查与填写模板见 [Cocos手测](testing/cocos-manual-checklist.md)。原作OCR保留为历史设计参考，不是本项目测量。
